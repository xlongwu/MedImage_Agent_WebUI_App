# 多 Agent 状态模型、持久化与恢复方案

> 状态：Proposed；G1/G3 实施依据

## 1. 单一顶层状态

`AgentLifecycleRecord` 继续是用户任务唯一权威状态。Team 状态只解释规划审查进度，不新增第二套 `WAITING_FOR_APPROVAL`、execution、completed 或 canceled 顶层状态。

切换到阶段十四 contract 时，`AgentLifecycleRecord` 的当前 schema 必须新增并持久化：`planning_mode`、`planning_team_id` 和单调递增 `planning_team_epoch`。这三个字段是“当前 planning attempt 绑定”的唯一权威来源；不按时间选择 latest Team，也不从 Team 列表猜测当前 advisory。所有当前消费者同步更新，不保留旧 lifecycle schema reader。

```text
AgentLifecycleRecord
├─ AgentPlanningBaseContext         # 当前 planning epoch 的十 section 不可变基础快照
├─ AgentHarnessContext v4           # single 的 empty advisory 或 Team 后的最终 Harness 输入
└─ AgentTeamRecord?                 # 每个 lifecycle 最多一个活动 Team
   ├─ AgentTeamContextSnapshot      # 引用 Base，并保存三个角色投影身份
   ├─ AgentTeamWorkItem x 3         # 固定角色，全部绑定 team_epoch
   │  └─ AgentTeamModelCallRecord x 1..2
   ├─ AgentTeamFinding x 0..24
   ├─ AgentTeamAdvisory?            # 确定性聚合产物
   ├─ AgentTeamEvent x N
   └─ AgentTeamWakeRecord x N
```

## 2. 状态合同

### 2.1 Team

```text
READY -> RUNNING -> AGGREGATING -> COMPLETED
READY/RUNNING/AGGREGATING -> NEEDS_ATTENTION
READY/RUNNING/AGGREGATING -> CANCELED
READY/RUNNING/AGGREGATING -> FAILED
```

`COMPLETED` 只表示 planning advisory 已冻结，不表示计划、执行或科学任务完成。
`COMPLETED`、`NEEDS_ATTENTION`、`CANCELED` 和 `FAILED` 均为 sealed terminal Team 状态；若需要重新审查，必须创建新 planning epoch/Team，不得重开旧 Team。

### 2.2 Work Item

```text
PENDING -> CLAIMED -> MODEL_STARTED -> VALIDATING -> COMPLETED
VALIDATING -> RETRY_READY -> CLAIMED -> MODEL_STARTED
VALIDATING -> FAILED
MODEL_STARTED -> INDETERMINATE
PENDING/CLAIMED/MODEL_STARTED/VALIDATING/RETRY_READY -> CANCELED
```

`RETRY_READY` 只允许一次 schema repair，repair 必须创建新的 `AgentTeamModelCallRecord` 并绑定原调用；第二次校验失败直接 `FAILED`。`INDETERMINATE` 不得自动重试，并使 Team 进入 `NEEDS_ATTENTION`。

### 2.3 Wake

复用 Agent Task wake outbox 的 `PENDING -> CLAIMED -> CONSUMED/RETRY` 语义，但使用独立 team wake 表和 idempotency key，避免 Team worker 与顶层 planning worker 竞争同一记录类型。

## 3. Pydantic 记录

在 `src/backend/app/schemas/agent_team.py` 新增 Team 从属记录；`AgentPlanningBaseContext` 与 `AgentHarnessContext v4` 位于 `schemas/agent_harness.py`。全部 `frozen=True, extra="forbid"`：

| 记录 | 核心身份/绑定 |
|---|---|
| `AgentPlanningBaseContext` | planning epoch、project/lifecycle、十个 section/hash、evidence/policy/redaction/hash；不含 advisory |
| `AgentHarnessContext v4` | base context ref/hash、typed team advisory（single 为空）、最终 context/section hash |
| `AgentTeamRecord` | team/epoch/project/lifecycle、mode、status、snapshot hash、policy/model/consent/budget、lease/fencing、advisory ref |
| `AgentTeamContextSnapshot` | team epoch、planning base context ref/hash、三个 role context hash、consent epoch/hash、redaction/policy/prompt/schema 版本 |
| `AgentTeamWorkItem` | team/role、dependency、attempt、request hash、status、lease/fencing、deadline |
| `AgentTeamModelCallRecord` | team/epoch/work item/role、pre-network/request/provider identity、status、response hash、usage、repair/indeterminate |
| `AgentTeamFinding` | team/work item/model call/context/ref/finding hash |
| `AgentTeamAdvisory` | accepted/rejected finding refs、blocking codes、conflicts、coverage、advisory hash |
| `AgentTeamEvent` | command/idempotency/source/type/payload hash/occurred_at |
| `AgentTeamWakeRecord` | step key、reason、status、lease、available_at、attempt count |

所有 durable JSON payload 包含 `_schema_version` 或 schema model 中的 `schema_version`，并只存在一个当前格式；不实现旧版本读取或双写。

## 4. SQLite 表与索引

在当前 desktop/project SQLite store 中新增：

| 表 | 唯一约束/索引 |
|---|---|
| `agent_planning_base_contexts` | PK `base_context_hash`；unique lifecycle/planning_epoch；index project/lifecycle |
| `agent_teams` | PK `team_id`；unique lifecycle/team_epoch；index project/status |
| `agent_team_contexts` | PK `snapshot_hash`；只保存 Base ref 与角色投影；index project/lifecycle/team |
| `agent_team_work_items` | PK `work_item_id`；unique team/role/attempt；index status/available_at |
| `agent_team_model_calls` | PK `model_call_id`；unique work_item/request_hash/attempt；index team/status/started_at |
| `agent_team_findings` | PK `finding_id`；unique finding_hash；index team/role/severity |
| `agent_team_advisories` | PK `advisory_id`；unique team/context_hash/advisory_hash |
| `agent_team_events` | PK `event_id`；unique command_id/event_type；index team/occurred_at |
| `agent_team_wake_outbox` | PK `wake_id`；unique team/step_key；index status/available_at |

最终 `AgentHarnessContext v4` 继续由现有 `agent_harness_contexts` 表和 `AgentHarnessAttempt.context_hash` 保存/引用；该表不保存 Base v1。`agent_planning_base_contexts` 是 Base v1 的唯一存储，`agent_team_contexts` 只保存 Team 对 Base 的引用和角色投影，不复制最终 Harness v4。

表只保存结构化状态和安全摘要，不保存完整 provider response、完整 prompt、rawdata 或任意文件内容。

## 5. 事务边界

必须原子提交：

1. lifecycle current Team epoch CAS + 创建 Team/context/work items/event/wake 必须原子提交。
2. claim work item + fencing token + `AgentTeamModelCallRecord(status=started, network_called=false)`。
3. 网络调用前再次校验 consent epoch/hash，并原子切换 `network_called=true`；校验失败则取消且不发请求。
4. model response hash/usage/status + validated finding 集 + work item terminal state + event + 下一 wake。
5. 聚合 advisory + Team completed + event + 顶层 planning wake，全部绑定同一 current epoch。
6. cancel Team + 非终态 work item canceled + pending wake canceled + event。

模型网络调用永远在事务之外，但其开始记录必须先持久化；返回后按 idempotency key 完成。崩溃恢复先查 started call：

- 有完整 provider response hash 和已验证 finding：只完成本地落库，不重复调用。
- 只有 started 且 provider 幂等查询不可用：标记 indeterminate/needs-attention，不盲目重试。
- 明确 pre-network：允许使用同一 request/idempotency key 重试。

`AgentTeamModelCallRecord` 状态固定为 `started -> completed|failed|indeterminate|canceled`；repair 使用新 record 并通过 `repair_of_model_call_id` 绑定原调用。记录 provider request identity（如可用）、network_called、response hash、input/output/cached token、latency 和 error code，但不保存完整 prompt/response。

## 6. Lease、Fencing 与并发

- Team Scheduler 是 lifespan-owned 单 owner 服务，但数据库仍按多实例竞争设计。
- claim 使用 compare-and-swap，写入 `lease_owner`、`lease_expires_at` 和单调递增 `fencing_token`。
- 完成、重试和取消必须匹配最新 owner + fencing token。
- 过期 Worker 的迟到结果被拒绝，不能覆盖新 owner。
- 同一 lifecycle 同时只允许一个活动 Team；重复 create command 幂等返回原 Team。
- 同一 role 的同一 attempt 只允许一个成功 finding set。
- 创建新 Team 必须对 lifecycle `planning_team_epoch` 做 CAS 递增，并写入 `planning_team_id`；旧 epoch 的 wake、claim、finding、advisory、finalize 和 planning resume 全部拒绝。
- lifecycle 可以保留多个 terminal Team 供审计，但只有其 `planning_team_id + planning_team_epoch` 指向的 Team 能进入当前 planning request。

## 7. 重启恢复矩阵

| 崩溃点 | 恢复动作 | 禁止结果 |
|---|---|---|
| Team 创建事务前 | 无记录，command 可安全重放 | 半个 Team |
| Team 创建事务后、notify 前 | startup rescan 找到 pending wake | 丢失 Team |
| Base v1 已冻结、planning worker 重启 | 按 current epoch 加载同一 base ref/hash | 重建或原地修改 base |
| model started 前 | 重新 claim | 重复 work item |
| model started 后、响应前 | indeterminate 或 provider 幂等恢复 | 盲目重复收费调用 |
| findings 落库后、work item 完成前 | 根据 finding hash 完成本地状态 | 重复 finding |
| 三角色完成后、advisory 前 | 重新运行纯聚合 | 第二份不同 advisory |
| advisory 完成后、planning wake 前 | 同事务保证 wake 已存在 | advisory 永不进入规划 |
| plan 持久化后、Team finalize 重放 | planner command/idempotency 命中 | 第二个 Reviewed Plan |
| 新 epoch 已创建、旧 wake/response 迟到 | current binding + epoch/fencing 拒绝 | 旧 advisory 污染新规划 |
| consent 在 snapshot/claim/network/response 各点撤销 | 调用前复验；迟到响应拒绝应用 | 撤销后继续数据外发或应用 finding |

## 8. 取消与终止

- 用户取消顶层 Agent Task 时，同事务/有序命令取消活动 Team 和未终态 work item。
- 已在 provider 网络中的调用无法保证物理取消时，记录 cancel requested；迟到响应不应用。
- Team terminal 不自动取消顶层 lifecycle；`FAILED/NEEDS_ATTENTION` 映射为 backend-authoritative attention 状态。
- 应用 shutdown 停止 claim 新 work，等待有界 grace period，释放 owned lease；不能删除状态。

## 9. Store Protocol

`ProjectStore` 只增加 typed Team repository 方法。Route 不得直接访问 concrete `SQLiteDesktopStore`，Service 构造中不得隐式创建 store。

最小方法族：CAS lifecycle current Team binding，create/get/list team，add/get context，create/claim/update/list work item，start/mark-network/complete/get/list model call，add/list finding，add/get advisory，append/list event，enqueue/claim/complete/retry wake，以及上述事务组合方法。

- [ ] SQLite 新连接/应用重启后 Team、base/context、work item、model call、finding、advisory、event、wake 可完整重载。
- [ ] Model call started/network/completed/indeterminate/repair 状态可重载，并能区分 pre-network 与 post-network 崩溃。
- [ ] 每个事务边界故障注入后无半写状态。
- [ ] 两个 scheduler 竞争同一 work item 时只有一个 owner。
- [ ] lease takeover 后旧 fencing token 的迟到结果被拒绝。
- [ ] create/cancel/finalize command 重放幂等。
- [ ] 多个 terminal Team、epoch CAS、旧 wake 和迟到 finalize 不能改变 lifecycle 当前 binding。
- [ ] consent 四时点撤销后不继续未授权调用、不应用迟到响应。
- [ ] GET/list 只读，不 claim wake、不 reconcile、不迁移状态。
- [ ] 数据库中不出现 prompt/provider response/rawdata/credential 明文。
