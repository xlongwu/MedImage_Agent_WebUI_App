# 生产多 Agent 逐文件实施台账

> 状态：Proposed；按 Gate 顺序执行，G0 未通过不得开始 G1

## 1. 实施所有权

- 每个 Gate 同一时间只有一个实现 owner；reviewer 只提出问题，不并行改同一文件。
- 每完成一个任务必须回到本台账和对应专项文档核对。
- 新 contract 一次性同步所有当前消费者，删除被替换字段和测试，不建立兼容层。
- 受保护执行面只做 binding 验证所需的最小修改：dispatch 算法、runtime 和 runners 不重构，但 Gateway 在 consume/dispatch 前必须调用一个 fail-closed Team ticket policy verifier。

### T4.4 Ticket policy binding 与 dispatch preflight

- **文件**：MODIFY `src/backend/app/schemas/execution_ticket.py`、`src/backend/app/services/execution_ticket_service.py`、`src/backend/app/services/reviewed_execution_service.py`、Approval/Reviewed Execution 组合服务、项目 multi-agent consent 更新服务；CREATE `src/backend/app/services/team_ticket_policy_verifier.py` 和启动期 policy reconciler；在 `src/backend/app/runtime/execution_gateway.py` 的 `consume()`/dispatch 前接入最小 verifier hook；新增 `tests/unit/test_agent_team_ticket_policy.py` 及 integration race tests。

## 10. 明确不修改的执行面

除经 T4.4 批准的最小 ticket verifier 接点外，不修改：

- scientific kernels 和 node registry plugins；
- Pipeline Runtime 和 node runners；
- Sandbox Process Runner 和 Windows restricted-token 实现；
- Execution Gateway dispatch 算法；只允许在 `consume()`/dispatch 前调用 `TeamTicketPolicyVerifier`，不新增第二 dispatch 路径；
- MATLAB/SPM/DPABI/GPU/DICOM 默认能力开关；
- 应用版本和 Release 产物。

### 10.1 Blast Radius Map

| 表面 | 影响级别 | 原因 |
|---|---|---|
| Agent schema、planning service、Harness model adapter | High | contract 和规划输入 identity 变化 |
| ProjectStore/SQLite、scheduler、lifespan wiring | High | 新 durable 从属状态和恢复路径 |
| Reviewed Plan/Approval Summary identity | High | 必须绑定 Team advisory，但审批顺序不变 |
| Agent Task read model/API/frontend/i18n | Medium | 新可选 Team 投影和用户状态 |
| Trace/Replay/Invariant/Operations | Medium | 新安全摘要、回放规则和指标 |
| Pipeline Runtime/runner/scientific kernels | None | 明确不接入也不修改 |
| Sandbox/Gateway dispatch | Low | 仅新增 consume 前 fail-closed Team ticket policy verifier；dispatch 算法和 runner 路径不变 |
| Memory authority/content | None | Reviewer 不查询或写 Memory，只消费父 context 中已冻结摘要 |
