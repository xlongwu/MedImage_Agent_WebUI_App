# 多 Agent 人工评审与实施检查清单

> 状态：待评审；本文件记录未来实施 Gate，不表示当前已批准生产编码

## 1. 方案评审

- [ ] 已确认首期只做规划前的三个只读 reviewer。
- [ ] 已确认不实现递归、多 Agent 执行、动态角色、自由 mailbox、MCP/tool 继承。
- [ ] 已确认 `single_agent` 默认，`multi_agent` 每任务显式选择，首期没有 `auto`。
- [ ] 已确认显式 Team 失败进入 handoff，不静默伪装为已完成 Team 审查。
- [ ] 已确认 Coordinator 控制面确定性，首期不增加 synthesis model。
- [ ] 已确认最终计划仍只由现有 AgentPlanningService/Harness 主链生成。

## 2. G0 数据与能力评审

- [ ] pilot 至少 30 个，独立 held-out acceptance 至少 150 个并按 eligible/ineligible/adversarial 分组。
- [ ] 每个 case 有双人标注和必要的第三人裁决。
- [ ] 无 rawdata、PHI、credential、完整 prompt、完整 response、绝对研究路径。
- [ ] manifest/report hash 已冻结并记录。
- [ ] manifest 只含输入和人工 labels，不含可手工伪造的 baseline/candidate 运行指标。
- [ ] 隔离 runner 实际执行 baseline/candidate，并绑定 source tree、provider/model、role/prompt/schema/policy/context/request/response hash。
- [ ] G0 与生产复用同一 role registry 和 pure aggregator。
- [ ] 召回、误报、一致性、成本、延迟、人工步骤和零退化 Gate 全部通过。
- [ ] capability reviewer 明确批准进入 G1；批准引用精确 hash。

## 3. Contract 与状态评审

- [ ] AgentLifecycleRecord 仍是唯一顶层任务状态。
- [ ] Team schema frozen、extra-forbid、versioned、无兼容读取。
- [ ] 每 lifecycle 最多一个活动 Team。
- [ ] lifecycle 持久化 current Team id/epoch；多个 terminal Team、旧 wake 和迟到 finalize 不能改变当前 planning binding。
- [ ] Team completed 只表示 advisory 完成，不表示计划或任务完成。
- [ ] SQLite transaction、idempotency、lease、fencing、restart 和 cancel 语义明确。
- [ ] Team model-call record/table/store 能区分 pre-network、post-network、repair 和 indeterminate。
- [ ] Base Context 与最终 Harness Context 是两个独立不可变快照；reviewer 输入不依赖尚未生成的 advisory。
- [ ] Base v1 只存于 `agent_planning_base_contexts`，最终 Harness v4 只存于 `agent_harness_contexts`，Team context 只保存 Base ref 与角色投影。
- [ ] 共享 model adapter 不混淆调用账本：Team reviewer 写 Team model-call，single/main Harness 保留 Harness `ModelCallRecord`。
- [ ] GET/list 不产生 reconcile 或任何状态副作用。

## 4. 权限与数据评审

- [ ] 三角色输入 section 和禁止字段逐项确认。
- [ ] Worker 无 filesystem、shell、network、MCP、Memory 写、Approval、Ticket、Gateway、runner。
- [ ] provider 调用只能通过统一 structured adapter。
- [ ] project/lifecycle/team/context/ref 每层均校验。
- [ ] project consent epoch/hash 进入 snapshot/work/model/advisory，且每次 provider 调用前复验。
- [ ] rawdata 和登记源数据只读，且不进入 provider payload。
- [ ] prompt injection、未知字段/code/ref 和 forbidden suggestion 安全拒绝。

## 5. 规划、审批与执行评审

- [ ] multi advisory 只是 planner 输入，不存在 TeamPlan 或第二 planner route。
- [ ] AgentPlanningBaseContext 先于 Team 冻结且不含 advisory；AgentHarnessContext 当前版本在 Team 后包含 typed team_advisory；`advance_planning -> _harness_or_plan` 是唯一接入 seam。
- [ ] PlanningRequest、Reviewed Plan、Approval Summary 覆盖 Team context/advisory/model/policy hash。
- [ ] 任一 binding 漂移都会使旧审批无效。
- [ ] ticket 冻结 Team policy/consent/base/context/advisory/role/projector/adapter/aggregator identity；approve、dry-run、issue、consume 四处复验责任已实现。
- [ ] consent 更新与启动期 policy reconciler 会 revoke issued-not-dispatched ticket；Gateway consume 前 verifier 能关闭签发后竞态且不新增 dispatch 路径。
- [ ] Team 阶段 dry-run、ticket、gateway、runner 调用为 0。
- [ ] plan-only 的 approval/execute 路径调用为 0。
- [ ] 多 Agent 不改变能力等级或科学真实性定义。

## 6. API、前端和运维评审

- [ ] create request 只有 `single_agent|multi_agent`。
- [ ] 显式 multi 不能绕过确定性 eligibility；ineligible 时 Worker 调用为 0。
- [ ] Team summary/findings/events project-scoped、分页、脱敏、只读。
- [ ] 前端覆盖 loading/disabled/empty/running/attention/completed/failed/canceled。
- [ ] Team completed 不显示为 execution completed。
- [ ] en/zh-CN catalog、client、type、controller 和组件测试同步。
- [ ] Trace、Replay、Invariant、Operations 和 alert 覆盖 Team。
