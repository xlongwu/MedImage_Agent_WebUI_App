# 阶段十四：人工授权与启用条件

> 2026-10-13 更新。本文只登记不能由自动化替代的授权与外部判断；G1–G7 不再要求逐 Gate 人工签字。当前范围和实现顺序以 `00_阶段规格与实施总览.md` 为准。

## 离线源码实现

默认关闭、使用 fake provider、隔离合成数据且不访问外网或研究数据的实现可直接开始。Contract、store、只读 worker、规划绑定等安全与正确性由对应 focused checks 验证，不再为每个模块重复建立人工评审、签字表或全量测试门。

## 真实评测前需要的人工决定

- 批准真实 Trace/Replay 的数据来源、导出范围和不可逆脱敏政策；研究数据不得未经授权进入评测集。
- 如需联网，明确批准 provider/endpoint、模型、预算和总调用上限；未批准时网络调用保持关闭。
- 在查看评测结果前固定评测集和指标。样本量按 `01_真实脱敏TraceReplay准入方案.md` 及现有 schema 执行；自动 runner 和报告负责计算指标、hash 与失败原因，不要求人工重复核算。
- 评测不达标时维持 `single_agent`。只有是否启用真实 provider 或研究项目 opt-in 需要维护者决定。

## 发布与可见体验

真实 provider 或研究项目 opt-in 之前，核对相应授权和 G0 结果；正式发布仍走项目现有 release 授权。packaged build、sidecar、renderer 和恢复检查按其对应阶段运行，不作为离线源码实现的先决条件。

如需人工检查 GUI 可读性，在一个当前 exact-SHA 候选上完成一次双语、多状态 walkthrough；由 `specs/待人工审核校验清单.md` 的 P-03 统一跟踪，不再按 A-06…A-13、A-16 分别重复截图或签字。

## 仍须保留的技术边界

- 全局 flag 和项目 consent 默认关闭；未授权时不调用真实 provider。
- Worker 无文件、shell、网络、MCP、审批、ticket、gateway 或 runner 能力；最终计划仍由唯一 planner 生成。
- 任何 Team advisory 必须进入现有 Reviewed Plan、Approval Summary 和 Execution Ticket 绑定；审批顺序、plan-only 零执行及后端状态权威不变。
- 跨项目数据、越权输入、身份/hash 漂移和执行副作用须由对应 focused tests 验证；失败时 fail closed。
