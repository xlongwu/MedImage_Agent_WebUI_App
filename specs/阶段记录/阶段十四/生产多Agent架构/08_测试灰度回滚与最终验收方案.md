## 2. 必须证明的负面行为

以下测试必须用 spy/assert-not-called 证明为 0：

- Worker/Coordinator 调用 filesystem、shell、subprocess、MCP、Gateway、runner。
- 规划或 Team 阶段调用 dry-run、ticket、dispatch。
- plan-only 创建 approval、run 或数值产物。
- GET/list 触发 reconcile、claim、notify 或状态迁移。
- `team_eligible=false` 或 flag/consent 关闭时启动 Worker。
- manifest 手工填写 baseline/candidate 指标绕过真实 gate runner。
- safety reviewer 缺失时生成可审批 advisory。
- context/advisory hash 变化后复用旧 Reviewed Plan/Approval Summary。
- lifecycle current Team epoch 变化后应用旧 wake/finding/advisory/finalize。
- consent 在 snapshot/claim/network/response 任一点撤销后继续调用或应用响应。

## 3. 性能与稳定性

在批准的真实脱敏集和本地压力 fixture 上验证：

- Team size 固定为 3，任何配置不能突破 hard cap。
- 全局并发受 CPU、available memory、provider rate 和配置上限共同限制；遥测缺失时串行或拒绝。
- 输入 token、调用次数和 deadline 超限前停止新调用。
- 100 个并发 Team fixture 不产生重复 claim 或跨项目数据。
- Worker 到达顺序随机化后 advisory hash 一致。
- 生产与 G0 复用同一 role registry/aggregator；修改其 hash 后旧 G0 approval 失效。
- 应用 shutdown/restart 后无 orphan scheduler、后台线程或 owned process。

## 5. 灰度策略

### Stage A：代码存在但不可启用

- 只有 G0 已通过并批准进入 G1 后才可能存在生产代码；approved manifest/report/source/role/aggregator hashes 未配置或不匹配时，即使 env flag 为 1 也 fail closed。
- 运行 schema/store/worker 的自动化测试，不在真实项目显示入口。

### Stage B：内部临时项目

- 仅 synthetic/脱敏项目；global flag + project consent + per-task mode 三门齐全。
- 监控安全拒绝、成本、延迟、冲突和恢复。

### Stage C：批准研究项目手动 opt-in

- 逐项目人工批准，用户每任务显式选择。
- 不启用 `auto`，不扩大 Worker 数据类别或能力。
- 设定观察窗口和停止条件。

### Stage D：稳定生产能力

- 仍默认 single；Team 作为高级显式能力。
- 是否设计 `auto` 必须另立阶段和新方案，本阶段不预留隐式自动路由。

## 6. 停止与回滚条件

任一条件触发立即关闭全局 flag，并停止创建新 Team：

- 安全、项目隔离、审批或科学真实性出现任何退化。
- 发现 Worker/Coordinator 可达写入或执行面。
- advisory/plan/approval binding violation 非零。
- false blocker 超过 3%，或关键遗漏召回未保持 +10 个百分点。
- 调用量、token 或 P95 时延连续超过批准 Gate。
- 重启产生重复模型调用、finding、advisory 或 plan。
- Trace/API/日志发现敏感数据泄露。

回滚动作：

1. 关闭 `MEDIMAGE_MULTI_AGENT_ENABLED`。
2. Scheduler 停止 claim 新 work；活动 Team 有界取消并记录事件。
3. 保留 Team 记录用于只读审计，不删除或改写历史。
4. 新任务走 single；显式 multi request 返回 disabled reason。
5. 人工 Approval 记录本身保持不可变且不声称存在通用 Approval revoke；但关闭多 Agent flag 或改变 consent/policy 会使未 dispatch 的 multi-agent 执行资格失效，必须按下列状态矩阵在 approve/dry-run/issue/consume preflight 拒绝，并对 issued-not-dispatched ticket 记录权威 revoke。

### 6.1 Rollback/安全事件状态矩阵

| 当前状态 | 处理 |
|---|---|
| Team READY/RUNNING/AGGREGATING | 停止 claim、取消未调用 work；迟到响应拒绝应用 |
| Team COMPLETED、尚未生成 Reviewed Plan | current planning binding 标记不可继续，创建新 single task |
| WAITING_FOR_APPROVAL | approve preflight 重新校验 multi-agent global policy/consent/role/aggregator hash；失配则拒绝审批 |
| 已审批、dry-run/ticket 前 | reviewed execution preflight 重新校验相同 binding；失配则不运行 dry-run、不签发 ticket |
| ticket 已签发但未 dispatch | `ExecutionTicketService.revoke()` 记录权威撤销；Gateway 继续按现有 ticket status fail closed |
| ticket 已消费或 run 正在执行 | 关闭 Team flag不能伪称立即终止；按现有后端权威 cancel/monitor/incident procedure 处理并报告能否停止，不新增旁路 kill |

Team 的 `multi_agent_policy_hash`、consent、base/context/advisory、role registry、context projector、model adapter 和 aggregator hash 必须进入 Approval Summary/Ticket binding，并在 approve、dry-run、ticket issue 和 ticket consume/dispatch 前复验。consent 更新服务与启动期 policy reconciler 负责主动 revoke issued-not-dispatched ticket，Gateway 的 `TeamTicketPolicyVerifier` 负责关闭最后竞态。该最小 binding 校验是受保护执行面允许的唯一新增接点；不得重写 Gateway dispatch 算法。

回滚不是兼容层：生产代码仍只有当前 Team schema，不读取旧格式或双写。

## 7. 最终验收矩阵

| 领域 | 验收 |
|---|---|
| 真实收益 | G0 真实脱敏 Gate 和人工 capability review |
| 架构 | 单 lifecycle、单 planner、单 Approval、单 Gateway |
| 状态 | durable Team/work item/finding/advisory/wake，重启可恢复 |
| 权限 | Worker 只读，无 tool/write/execute/approval |
| 安全 | project isolation、rawdata、path、prompt injection、hash drift |
| 科学 | 不改变算法和能力等级，不虚假 computed/validated |
| API/UI | contract/i18n/所有状态/只读详情/后端权威 |
| 审计 | Trace/Replay/invariant/operations 完整且脱敏 |
| 性能 | 调用/token/P95/人工步骤在 Gate 内 |
| 桌面 | build、sidecar、renderer、packaged smoke、进程清理 |

## 8. 最终 Definition of Done

- [ ] G0-G7 顺序完成，所有 Gate 有证据和人工签字。
- [ ] G0 报告来自真实隔离 runner，端到端包含 reviewer/repair/retry/主 planner，并通过置信区间门槛。
- [ ] G4-G6 完成后已用最终 production source tree、role/context/adapter/aggregator 重新运行 G0，旧评估 hash 未被沿用。
- [ ] 生产代码没有第二规划链、第二顶层状态或第二执行入口。
- [ ] 所有当前消费者切换到唯一新 contract，废弃字段/实现零引用。
- [ ] focused、full backend、frontend、Electron、Windows packaged smoke 全部通过。
- [ ] 所有环境门控 skip 有精确原因，不跳过本阶段回归。
- [ ] 文档、README、配置、能力矩阵和 PROJECT_STATE 与真实实现同步。
- [ ] `git diff --check`、秘密扫描、生成物、进程和 `git status` 审查通过。
- [ ] 全局默认关闭、项目默认无 consent、首期无 `auto`。
- [ ] 无未解释风险、临时代码、虚假成功或用户数据产物。
