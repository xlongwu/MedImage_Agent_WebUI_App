# 阶段七：多 Agent 延期条件与后续评估方案

> 状态：已实施离线预检，待人工评审真实 Trace/Replay 证据
> 依赖：阶段一至六全部完成
> 本阶段默认结论是继续使用单 Agent；只有证据满足门槛时才提出新的生产实现任务。

## 1. 目标

避免因为“可以并行”就直接增加生产多 Agent。先用离线评估证明单 Agent 的问题确实来自审查不足或上下文过载，并证明多 Agent 的收益大于额外成本。

## 2. 当前保持不变的规则

- `AgentHarnessAttempt.mode` 继续固定为 `single_agent`。
- 当前多 Agent 设计只用于离线分析和评估，不接生产任务生命周期。
- 不新增监督 Agent、递归派生、Agent 间聊天、共享自由文本黑板或动态角色。
- 不允许任何评审 Agent 调用工具、修改计划、审批、创建执行票据或执行。
- 生产状态、预算、审批和执行边界继续只有一个所有者。

## 3. 进入评估的前提

阶段一至六必须全部达到退出条件，并至少积累一批可回放的单 Agent 任务记录。以下任一项未满足，就停止本阶段：

- 仍存在两条规划路径。
- 模型动作仍是通用字典。
- 请求、上下文和动作哈希不完整。
- 重启或重复唤醒仍可能产生重复副作用。
- 审批摘要和执行票据未绑定执行环境。
- 运行时自检尚不能发现关键不一致。

## 4. 只评估一个最小方案

若满足前提，只评估“主规划者 + 最多三个只读评审者”：

- 科学合理性评审：检查输入、参数和前提是否匹配。
- 安全边界评审：检查路径、写入范围、审批和执行能力。
- 完整性评审：检查目标、决定、计划节点和输出是否对应。

评审者只能读取同一个已冻结 `AgentHarnessContext`，输出固定数据结构：

```python
class AgentReviewFinding(BaseModel):
    reviewer_kind: Literal["science", "safety", "completeness"]
    severity: Literal["warning", "blocking"]
    code: str
    message_key: str
    input_refs: tuple[str, ...]
    suggested_change: str | None
```

主规划者不自动接受建议。确定性聚合器按错误码、级别和引用去重，阻断级检查结果转用户决定或阻止计划进入审批。

## 5. 离线评估数据

从已有 `Trace` 和 `Replay` 选择脱敏任务，至少覆盖：

- 仅规划。
- 缺少 BIDS 或预处理前提。
- ALFF/fALFF、ReHo、头动和 QC 目标。
- 中英文目标。
- 不支持目标。
- 环境不可用。
- 路径或写入根不安全。
- 模型服务返回非法动作。

不得复制 `rawdata`、原始图像、凭据或完整提示词到评估集。使用结构化测试样例、哈希和允许的最小摘要。

## 6. 对比指标和通过门槛

同一批任务比较单 Agent 与只读评审方案：

| 指标 | 计算方式 | 进入生产设计的最低门槛 |
|---|---|---|
| 关键遗漏召回 | 人工标注阻断问题中被发现的比例 | 提升至少 10 个百分点 |
| 新增误报 | 多 Agent 新增但人工判断不成立的阻断级结果 | 不高于任务数的 3% |
| 计划一致率 | 相同输入重复运行得到相同结构化结论 | 不低于当前单 Agent |
| 模型调用量 | 每个任务的平均调用次数 | 不超过单 Agent 的 2.5 倍 |
| 输入量 | 每个任务总输入 token | 不超过单 Agent 的 2 倍 |
| 完成时间 | 第 95 百分位规划时间 | 不超过单 Agent 的 1.8 倍 |
| 人工操作 | 用户需要回答和审批的次数 | 不增加无必要步骤 |

若收益只来自更好的确定性检查、提示词或上下文，应把改进留在单 Agent，不进入多 Agent。

## 7. 必须验证的失败场景

- 一个评审超时，其他结果仍能确定性聚合。
- 同一问题被多个评审重复提出。
- 评审结论相互冲突。
- 评审引用不存在、跨项目或不在冻结上下文。
- 评审提出命令、路径、审批或执行建议。
- 预算用尽或模型服务不可用。
- 主规划结果和评审结果顺序不同。

所有情况都必须安全拒绝，且不能扩大主 Agent 权限。

## 8. 生产实现前必须重新批准的内容

即使离线指标达到门槛，也必须另建方案并人工批准：

- 评审结果数据结构和固定角色。
- 每个角色的上下文可见范围。
- 总预算和每角色预算。
- 超时、重试和部分失败规则。
- 检查结果聚合和冲突处理。
- `Trace`、`Replay` 和运行时自检扩展。
- 前端如何展示阻断级结果。
- 为什么单 Agent + 确定性检查不足。

本文件不授权修改生产 `mode`、启动并行模型服务调用或增加 Agent 工具。

## 9. 风险和处理

| 编号 | 风险 | 处理 | 证明方式 |
|---|---|---|---|
| H-09 | 多 Agent 只是重复同一错误 | 固定不同评审职责并统计新增有效问题 | 人工标注对比 |
| H-09A | 成本和延迟明显上升 | 设置调用量、输入量和第 95 百分位门槛 | 离线报告 |
| H-09B | 多个 Agent 形成第二执行所有者 | 评审只读且没有工具 | 依赖图和调用检查 |
| H-09C | 冲突由模型自由裁决 | 只用确定性聚合；无法合并则交给用户 | 冲突测试样例 |
| H-09D | 评估数据泄露研究内容 | 只用脱敏结构化测试样例 | 数据清单人工审查 |

## 10. 本阶段交付物

本阶段只交付：

1. 固定评估集清单和脱敏说明。
2. 单 Agent 基线结果。
3. 只读评审方案结果。
4. 指标对比、误报样例和失败样例。
5. “继续单 Agent”或“提交新的生产多 Agent 方案”的明确结论。

不修改生产 Agent 代码，是本阶段的正常结果。

### 当前实施结果（2026-08-16）

- 固定评估合同、确定性聚合器和无副作用运行脚本位于
  `src/backend/app/schemas/agent_eval.py`、
  `src/backend/app/services/multi_agent_evaluation_service.py` 与
  `scripts/run_multi_agent_evaluation.py`；它们不接入生命周期、审批、票据、网关、
  runner、网络或项目存储。
- `tests/fixtures/agent_eval/multi_agent/manifest.json` 是 10 个无研究数据的
  synthetic 预检样例，覆盖本文件第 5 节规定的场景和中英文目标。它用于验证合同、
  聚合、成本计算与失败关闭行为，不能代替人工标注的脱敏 Trace/Replay 评估集。
- 使用 `python scripts/run_multi_agent_evaluation.py --summary` 的预检结果为：
  关键遗漏召回率从 0.30 到 1.00；误报阻断任务率为 0；结论一致率为 1.00；平均模型调用
  为 2.00；平均输入量为 1.50 倍；P95 时延为 0.75 倍；人工操作不增加。
- 该预检仍以 `MULTI_AGENT_EVAL_GATE_REDACTED_TRACE_REPLAY_REQUIRED` 失败关闭，
  因为仓库不包含可人工标注的真实脱敏 Trace/Replay 样本。结论为继续使用
  `single_agent`；不得把 synthetic 结果当作生产多 Agent 的准入证据。

真实评估开始前，人工评审者必须将每个样例的来源哈希、脱敏说明和阻断问题标注写入
冻结 manifest；只有届时全部指标仍达到本文件门槛，才能新建并人工批准生产设计方案。
