## 2. Required Behavior

### 2.1 Bounded reconciler

新增 `AgentTaskReconciler`，只处理已绑定 lifecycle/run/ticket 的任务：

```text
RUNNING + terminal run evidence
  -> OBSERVING
  -> EVALUATING
  -> GOAL_SATISFIED
     or DIAGNOSING -> RECOVERY_PROPOSED/HUMAN_HANDOFF
  -> stop
```

约束：

- 不使用 LLM 决定状态或恢复资格；
- 每次 reconcile 最大固定转移数；
- command id 由 lifecycle/run/observation hash 确定，重复调用幂等；
- unknown/conflicting/incomplete evidence 进入 HUMAN_HANDOFF 或 needs_attention，不无限轮询；
- 启动恢复由显式 startup reconciliation job 完成，GET endpoint 不写入；
- recovery proposal 绝不自动批准或执行。

### 2.2 Result Summary

结果只从 Goal Evaluation 和关联 Observation/Artifact Registry 生成：

- overall completion；
- completed/failed/excluded subject counts；
- QC 结论；
- artifact types 和稳定 links；
- limitation flags；
- validation/reload 状态；
- next recommended action。

`partial`、`preview_only`、`simplified`、`metadata_only` 必须面向用户转换为清楚限制，不能隐藏原始 capability evidence。

### 2.3 Recovery UX

默认卡片显示：失败范围、确定性诊断摘要、推荐 action、不会触碰的范围、是否需要新 plan/approval。用户操作只有批准恢复、查看详情、放弃并结束。修改参数、backend、node、path 或扩大 subject scope 必须重新 plan 和审批。

### 2.4 Technical Evidence

三层信息：

1. Agent 默认摘要；
2. Task Details：plan/stages/subjects/QC/artifacts/recovery history；
3. Technical Details：ticket、node contract、plan/goal hash、backend/resource decision、provenance、checksum、raw logs、validation JSON、artifact registry。

## 4. Detailed Tasks

1. 定义 terminal run evidence adapter，覆盖 Pipeline Runtime 与 native async progress，不以字符串猜测成功。
2. 实现 reconcile once 与 reconcile incomplete on startup；设置明确 batch limit 和 wall-time limit。
3. 对同一 terminal run 并发 reconcile，只有一个 observation/evaluation 链成功。
4. 将 failed goal 交给现有 diagnosis/proposal engine；unknown 直接 handoff。
5. 结果摘要校验 lifecycle、observation、evaluation、artifact project/run binding。
6. 建立 macro progress：准备数据、准备方案、执行处理、验证结果、完成；subject counts 优先于 node table。
7. Recovery card 只显示 recommended eligible candidate；其他候选放详情。
8. approved recovery 调用现有 endpoint/service；完成后自动刷新同一 task，不创建 UI 平行子任务。
9. Runs 展示 parent/child ticket、attempt、artifact lineage 和 audit；默认 Agent 页只给 evidence link。
10. 移除标准路径中的手动 Validation/Report/Refresh，但兼容页面保留调试能力。

## 5. Acceptance Criteria

- [ ] 正常 terminal run 自动到 GOAL_SATISFIED 或明确 needs_attention。
- [ ] 重复/并发/startup reconcile 不重复 observation、evaluation、proposal 或 runner dispatch。
- [ ] missing artifact、reload failure、partial subject 不显示完成。
- [ ] recovery proposal 不产生 filesystem/runner side effect。
- [ ] approved recovery 只处理批准范围并再次自动 evaluate。
- [ ] Results 卡片和 Runs evidence 对同一 artifact/checksum/status 一致。
- [ ] 普通页不要求用户手动 refresh/validation/report。
- [ ] 技术证据全可达、可复制、可审计。

## 8. Stop Conditions

- recovery 扩大原 ticket scope；
- 发现 native async restart 行为仍未满足 Phase 9 证据且会导致重复 dispatch。
