# 任务 10F：真实 E2E 与交互验收

> 状态：Source/docs acceptance completed；exact-SHA packaged app、可见 Electron 真实流程、
> installer 与发布对齐延期。
>
> 本文正文保留完整验收设计；当前 gate 结果以
> `evidence/阶段十_E2E验收记录.md` 为准，不能把 source 通过解释为 packaged/release 通过。
>
> 任务模式：Release and Packaging Mode + Scientific Validation Mode
>
> 交付目标：在 exact-SHA Windows packaged app 中证明 Agent-first 的 BIDS、DICOM 和 recovery 三条用户流程，同时验证交互指标、安全与科学真实性。

## 1. Test Matrix

### Flow F1：一句话 BIDS → FC

前置：项目已登记 BIDS/NIfTI、BOLD/T1/sidecar 和合规 atlas。

```text
选择项目
  -> 输入“完成标准预处理并生成基于 Schaefer Atlas 的 FC、QC 和报告”
  -> 审批计划
  -> 查看结果
```

验收：显式操作 <= 3；无手动 dry-run/validation/report/refresh/resource config；FC matrix 和中间必需 artifacts 可重载、已登记、provenance 完整。

### Flow F2：一句话 DICOM → preprocessing → FC

前置：10E `G10-5` 已通过，native DICOM release evidence 有效。

```text
选择项目
  -> 输入目标
  -> 必要时确认唯一数据/科学歧义
  -> 集中审批
  -> 查看结果
```

验收：显式操作 <= 4；conversion 与 preprocessing 均在 canonical ticket/gateway path；rawdata 完全不变。

若 10E 未通过，本 flow 必须标记 blocked，产品和发布说明只声明 BIDS Agent-first。

### Flow F3：单受试者失败 → 一次审批恢复

对三受试者任务注入 derivatives/work 范围内、可恢复的单受试者临时失败：

```text
Agent 自动 observe/evaluate/diagnose/propose
  -> 用户批准“仅重试失败受试者”
  -> Agent 自动恢复、observe、evaluate
  -> 查看结果
```

验收：不重跑成功受试者、不覆盖有效 artifact、不扩大 node/backend/path/subject scope、child ticket 一次性、最终结果如实显示。

## 4. Interaction Metrics

每条 flow 同时报告 baseline 与 Agent-first：

| Metric | Definition |
|---|---|
| top-level pages | 用户主动进入的一级页面去重数 |
| explicit operations | click/submit/selection that changes task state or reveals result |
| form fields | 用户必须输入/选择的字段数 |
| approvals | 独立人类授权次数；集中卡片算 1 |
| science decisions | 会改变科学含义的选择数 |
| technical concepts | 完成任务必须理解的内部概念数 |
| manual refresh | 用户主动刷新/轮询次数 |
| failure triage steps | 从失败到可行动建议的人工步骤数 |

自动页面加载、后台 polling、展开可选技术详情不计入标准操作，但必须在原始事件日志中可区分，防止人为美化数字。

## 5. Scientific and Safety Assertions

- 每个 subject 都有独立 terminal state；
- numerical artifacts 存在、可重载、shape/dtype 合理、checksum 稳定、已登记；
- Goal Evaluation criteria 与最终 UI result 一致；
- capability/limitation flags 未被丢弃；
- atlas 和 labels 已登记并许可明确；
- normalization affine baseline 的限制在结果摘要可见，不声称 SPM 数值等价；
- requested/selected compute backend 和 provenance 一致；
- rawdata filename/size/mtime/checksum 零变化；
- approval、ticket、gateway、audit、allowlist 和 path containment 全部有证据；
- recovery 只处理批准范围，quota/replay/expiry 受控。

## 6. Negative and Restart Scenarios

除三条 happy-path/controlled-failure flow 外，必须验证：

1. 缺 Atlas：停在提供资源/科学决策，不生成假 FC；
2. TR 冲突：停在科学决策；
3. stale approval summary：执行前拒绝；
4. project switch during polling：不串任务；
5. app 正常退出/强制终止/重启：不重复 dispatch；
6. missing artifact after terminal runtime：Goal Evaluation 不满足；
7. GPU unavailable：auto 清楚回退 CPU；
8. offline frontend：显示连接问题，不改变 backend task state；
9. expired/replayed recovery approval：runner 前拒绝；
10. cross-project task URL：404/安全错误。

## 9. Stop Conditions

- source tree 非 exact-SHA 或有未归属 dirty changes；
- packaged app 不是当前候选构建；
- rawdata manifest 发生任何变化；
- artifact/capability/Goal Evaluation 互相矛盾；
- 任何真实执行绕过 Ticket/Gateway；
- 为通过指标而隐藏必要科学决策或审批；
- 失败需要删除测试、降低 tolerance 或扩大 scope。
