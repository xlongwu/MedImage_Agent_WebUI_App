## Handoff

- **Status**：Implemented / Source Verified（2026-07-15）
- **Task Mode**：Architecture and Refactor Mode
- **Goal**：消除任何由 `pipeline_path + approved=true` 直接驱动 Runtime 的公开执行路径；以服务端签发的 `ExecutionTicket` 和唯一 `ExecutionGateway` 取代它。
- **Background**：审查结论将旧 `/api/agent/execute`、多套执行入口并存列为 P0。现有 `execute-reviewed` 已含验证、审批、审计与一致性校验，是迁移的基线而非需要另造的平行链路。
- **Current Behavior**：`agent_execute` 仅要求 `approved`，从固定路径推导 plan；`run_orchestrator_execute` 在 pipeline 不一致时只产生 warning 后仍调用 Runtime。`execute-reviewed` 直接 import `run_pipeline`；其他 route/service 也有直接调用点。
- **Required Behavior**：真实执行只由网关在 reviewed plan、Approval Gate、审计、一致性、allowlist 和 ticket 均通过后发起；旧入口不得再执行。
- **Non-goals**：不启用外部执行、不改变科学算法、不实现多用户认证、不在本任务实现状态机或节点 schema。

## Exact Anchors and Implementation Sequence

1. **建立特征化基线和入口清单**
   - 用路由到 `run_pipeline` 的静态调用链和 API 测试列出每个入口的请求、是否能真实执行、现有审批/审计、owner、迁移目标。
   - 将清单作为测试数据或受版本控制的开发文档；CI 中用 AST/受限 grep 防止公共 route 直接调用 Runtime。
   - DoD：每个执行入口有且仅有 `gateway`、`proposal/dry-run`、`deprecated` 三种判定。

2. **定义 ExecutionTicket 与存储接口**
   - 以 `ExecutionConsistencyInput` 的已有绑定字段为来源，新增 `execution_ticket_id`、schema version、issued/expiry/consumed/revoked 时间与 retry policy。
   - 票据包含：`project_id`、`reviewed_plan_id`、`plan_hash`、`approval_context_id`、`approved_actor`、`approved_node_ids`、`approved_backend_ids`、输入/输出 roots、allowlist fingerprint、`audit_id`、`max_retry_count`。
   - `ticket_id` 必须由服务端生成，payload 应有不可变 canonical hash；禁止从客户端 `actor` 或布尔 `approved` 推导授权。
   - DoD：持久化、过期、撤销、项目隔离、重复消费语义有单测且存储不写入永久桌面库测试实例。

3. **抽取唯一 ExecutionGateway**
   - 保持当前 `execute-reviewed` 的严格前置条件顺序：项目上下文 → plan validation → reviewed-plan match → Approval Gate → adapter/policy → pipeline 写入规则 → audit → consistency → ticket → dispatch。
   - 网关返回结构化 `submitted`/`executor_called`/ticket/audit/consistency 结果；前端不得从 HTTP 200 自行推断执行成功。
   - 不完整的入口不得由网关补猜 reviewed plan、approval 或路径。
   - DoD：`execute-reviewed` 是一个薄 HTTP 适配层，唯一真实 Runtime dispatch 位于网关。

4. **收敛与弃用现有入口**
   - `/api/agent/execute` 返回稳定弃用错误（建议 HTTP 410，包含迁移目标与不泄露路径的错误码），绝不调用 `run_orchestrator_execute`。
   - 对其余入口按清单改为网关或仅保留 proposal/dry-run；若其业务语义无法提供审阅契约，返回明确 `EXECUTION_CONTRACT_REQUIRED`。
   - 删除或隔离无调用者的旧 `run_orchestrator_execute`，并以测试证明没有公开引用。
   - DoD：没有 public route/service 可以绕过 gateway 触发实际 Runtime。

5. **收紧 Runtime API 并完成回归**
   - Runtime dispatch 接收 verified context；拒绝缺失/过期/已撤销或绑定不匹配 ticket。
   - 保留内部可测试性，但不得向 HTTP layer 暴露裸 `run_pipeline(config, path)` 执行能力。
   - DoD：篡改 project、plan hash、approval、allowlist、pipeline、输出根或 ticket 生命周期任一字段时，Runner 未被调用且审计可追踪。

## Acceptance Criteria

- [ ] 旧 `/api/agent/execute` 不再执行，且不存在 `approved=true` 绕过路径。
- [ ] 所有真实执行入口已在入口清单中收敛、明确停用或转为非执行接口。
- [ ] 每次真实执行均有 persisted reviewed plan、approval context、audit 和有效 ticket。
- [ ] plan/pipeline 不一致为硬失败，不再是 warning。
- [ ] 对 ticket 篡改、跨项目、过期、撤销、重放、allowlist 漂移和缺失审批均 fail-closed。
- [ ] 既有 approved Python synthetic smoke 仍通过；未设置外部执行门控时没有 external runner 调用。

## Safety Invariants

- rawdata 永远只读；ticket 的输入根不授予 rawdata 写权。
- Approval Gate、audit、safe allowlist 和环境门控不得被集中化重构删除或降级。
- 不能以“兼容性”为由让旧接口在缺少 ticket 情况下执行。
- 任何失配、未知或存储读取失败默认拒绝，不返回“成功但未执行”。

## Stop Conditions

- 发现任一外部执行入口无法迁移到完整审阅契约且产品方未接受弃用时，停止该入口的执行迁移并要求维护者决定迁移 UX；不得保留弱授权。
- 发现 ticket 持久化需要不可逆数据库迁移或破坏旧桌面数据时，先提交迁移设计和 rollback 测试再继续。
- 发现 Runtime 调用者属于另一个独立已批准任务，记录并协调 owner，不在本任务静默改写。
