## Exact Anchors and Implementation Sequence

1. **固化 capability 数据模型**：基于 7A ticket 生成 `ToolExecutionContext`；其中根目录必须已经 resolve，包含 `project_id`、ticket/audit ID、approved node/backend 集合、输入/输出 root 集合、allowlist fingerprint、expiry 和 retry scope。
2. **统一 path resolver**：对所有候选输入/输出路径使用 canonical resolve 和 `relative_to` 检查；拒绝绝对路径替换、`..`、符号链接逃逸、非预期驱动器/根目录和任何 rawdata 写入。策略错误应返回稳定的 `SafetyError`/错误码而不是 Python 原始异常。
3. **在 Runner 分发点强制**：在获取并调用 `get_node_runner()` 之间校验 node id、backend、ticket、输入/输出和所需外部执行权限。一个节点不应能通过自行读取 `ToolSpec` 或写路由逻辑绕过检查。
4. **迁移副作用接口**：对写文件、创建目录、调用 subprocess/MATLAB/DPABI/GPU 的 helpers，明确接受 context 或经 context 创建的受限 wrapper；不允许只靠约定传路径。
5. **分层回归**：先迁移 pure Python 合成节点，再分别迁移 native、DICOM、SPM、DPABI、GPU。未完成迁移的外部节点必须 fail-closed，不可暂时放行。

## Acceptance Criteria

- [ ] 无 ticket、ticket 过期/撤销、未批准 node/backend、allowlist 漂移均在 Runner 前失败。
- [ ] 合法输入读、合法输出写成功；越界读/写、rawdata 写、链接逃逸、非法绝对路径均失败且没有落盘副作用。
- [ ] 外部进程调用还需满足既有环境 gate、Approval Gate、ticket backend 许可和 capability context。
- [ ] 每个迁移 runner 不再把 node 参数中的任意路径当作授权来源。
- [ ] `ToolSpec` 可继续用于目录展示，但不再是唯一权限依据。

## Safety Invariants

- 不降低 safe path validation，不写用户 DICOM/BIDS/NIfTI/rawdata。
- 失败默认闭合；无法规范化路径或解析链接时拒绝。
- 不在 route/service 复制 Runtime 逻辑规避 protected module 改造。

## Stop Conditions

- 如果某个 runner 的真实文件/进程副作用无法定位或无法迁移到 context wrapper，禁止为其签发可执行 ticket，记录为 blocked node。
- 如果 Windows 链接/路径行为无法通过当前环境复现，添加平台特定测试计划并标记未验证；不能把该节点标为 fully enforced。
