## Handoff

- **Status**：Implemented / Source Verified（2026-07-15）
- **Task Mode**：Feature Bundle Mode
- **Goal**：以版本化、可执行的节点契约收紧 Planner/Validator，使“目录中存在节点”不再等价于“任意参数均可执行”。
- **Background**：审查结论指出多数节点缺少严格参数 Schema，Planner 仍主要是关键词路由器；7A/7B 已建立安全执行边界，本任务将执行前的语义校验前移到计划审阅阶段。

- **Non-goals**：不在本任务使 Planner 自主执行、自动选外部工具或建立长期记忆推荐；不宣称所有科学算法已独立参考验证。

## Exact Anchors and Implementation Sequence

1. **先定义最小 NodeContract**：包含稳定 `node_id`、`contract_version`、input/parameter/output schema、preconditions、postconditions、side effects、resource requirements、retry policy、idempotency policy、validation policy、capability level。契约自身必须可 JSON 序列化、可验证、可版本比较。
2. **按风险分批建模**：第一批为当前 safe allowlist 的纯 Python/contract 节点和测试 fixture；第二批 native preprocessing；SPM/DPABI/GPU/DICOM 仅在其外部 gate、输入输出和副作用明确后纳入。缺契约节点不进入可执行候选。
3. **让 Validator 成为唯一参数判定点**：对每个节点参数执行 schema 验证、默认值规范化、禁止附加字段（除非契约明确允许）、跨节点 artifact/shape/modality 兼容、前后置条件与资源限制检查。把规范化值、contract version、validation evidence 写入 reviewed plan 并由 ticket 绑定。
4. **收紧 Planner provider 边界**：provider response 必须解析为受限候选模型；无效 JSON/未知字段/未知节点/缺失信息时返回结构化失败或“需要人工补充”，不得静默回退成可执行方案。输出应说明候选依据、置信度、缺失前提与风险。
5. **为后续智能化预留但不启用**：多候选排序、历史参数推荐、长期记忆和局部重规划只能消费受审查的证据；在 Agent 专项评测集建立前不影响执行授权。

## Acceptance Criteria

- [ ] allowlist 内每个可执行 node 均有版本化 NodeContract；缺失契约默认不可执行。
- [ ] 无效类型、越界值、未知字段、输入输出不匹配、未满足前置条件、后端/资源冲突均在审阅前被拒绝。
- [ ] 规范化参数 hash 与 contract version 被记录并参与 7A ticket 一致性绑定。
- [ ] provider 的 malformed/自由文本/未知节点输出不产生 `ok=true` 或可执行计划。
- [ ] 遗留有效 fixture 的兼容适配受版本控制并有弃用测试；不兼容变更明确报错。

## Safety Invariants

- Node ID 不可重写；不以 schema 迁移偷换已批准 node 的语义。
- 不因 Planner 置信度高而跳过 Validator、Approval Gate、ticket 或 capability enforcement。
- 科学 capability level 必须与可重载数值产物和参考验证事实一致。
