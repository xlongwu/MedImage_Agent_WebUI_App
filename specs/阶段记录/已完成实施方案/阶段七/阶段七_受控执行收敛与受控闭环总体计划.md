## 1. Scope Anchor

**目标**：先消除并存的弱执行入口和仅描述性的路径权限，再以执行票据、运行时能力强制、持久化状态机和节点契约，构建“计划—审阅—执行—观察—受控恢复”的最小安全闭环。

**必须完成**：

- 所有会导致实际 Pipeline、节点、DICOM、预处理、DPABI/SPM/GPU 或重试执行的公开入口，均须纳入同一执行网关；不能验证审阅契约的旧入口必须停止执行。
- 运行时在 Runner 调用前验证票据、允许节点、输入根目录、输出根目录和安全 allowlist 指纹；不得只信任节点自行遵守 `ToolSpec`。
- 执行票据必须绑定 `project_id`、`reviewed_plan_id`、`plan_hash`、`approval_context_id`、批准节点/后端、输入/输出根目录、allowlist 指纹、过期时间、重试上限和审计 ID。
- 首先保留既有 Approval Gate、rawdata 只读、环境开关、审计、科学产物真实性和外部执行默认禁用等不变量。
- 状态机的任何自动动作只允许已列入票据且低风险、可重试、未超出配额的操作；节点集合、参数、后端、输入/输出范围变化必须回到审批。

**明确不做**：

- 不启用真实桌面 GUI 自动化，不放宽 mock-only GUI Guard。
- 不默认启用 MATLAB、SPM、DPABI、GPU 或 DICOM 真实执行。
- 不在本阶段引入“自由文本命令执行”、自治无限重试、临床用途，或将 LLM 输出视为执行授权。
- 不在未完成身份模型设计前，把 `approved_by="local-user"` 伪装成多用户可信身份。

**成功标准**：

- [ ] 代码库中没有能够绕过执行网关直接调用 `run_pipeline()` 的公开执行路由；保留入口只可返回迁移/拒绝结果，或在网关内完成同等校验。
- [ ] 无票据、过期票据、项目/哈希/allowlist 不匹配、越界路径和未批准节点均在 Runner 调用前被拒绝且产生可查询审计事件。
- [ ] 计划、审阅、审批、执行、观察、失败、重试提议和人工交接有单一持久化状态来源，非法迁移被拒绝。
- [ ] 每个已支持可执行节点都有可机器验证的参数、输入、输出和副作用契约；未建模节点只能停在非执行状态。
- [ ] 所有新增或改动的边界均有拒绝路径测试、回归测试和审计/状态持久化测试。

## 3. 目标架构与不变量

```text
用户目标 / 项目上下文
        ↓
Structured Planner → Deterministic Validator → Immutable Reviewed Plan
                                                    ↓
                                            Approval Context
                                                    ↓
                                             Execution Ticket
                                                    ↓
                                      Execution Gateway（唯一入口）
                                                    ↓
                        Capability Enforcement → Pipeline Runtime → Registered Runner
                                                    ↓
                           状态机 / 审计 / 产物验证 / 观察 / 人工受控恢复
```

`ExecutionTicket` 是本阶段的新边界对象，不是前端可自由填写的请求体。它只可由网关在以下前置条件同时满足后签发：已持久化的 reviewed plan、重新通过的验证、合格 Approval Gate、已持久化审计、有效项目上下文和当前 allowlist 指纹。Runtime 只接收经验证的票据对象或其不可变引用；不再把任意 `pipeline_path + approved=true` 视为授权。

## 4. 实施台账

### Phase 7A：执行入口收敛与执行票据（P0，阻塞后续执行功能）

**交付**：唯一执行网关、持久化/可验证的 `ExecutionTicket`、公开执行入口清单与迁移、旧 `/api/agent/execute` 的安全停用。

- 先用静态检索和路由测试建立“执行入口清单”；分类为真实执行、dry-run、仅元数据、废弃兼容入口。以代码调用链而非路由名判定，重点覆盖 `agent_routes.py`、`planner_routes.py`、`rsfmri_routes.py`、`task_routes.py`、`dashboard_routes.py`、`conversion_routes.py`、`preprocessing_routes.py`、`gpu_routes.py`、`dpabi_routes.py`。
- 将 `/api/agent/execute` 改为不可执行的弃用响应（建议 410 + 明确迁移错误码），而非在现有参数上做不安全的“自动转发”；该请求不具备 `reviewed_plan_id`、`plan_hash`、approval context 或票据所需材料。
- 从当前 `execute-reviewed` 路径中抽取执行前置检查及签发逻辑，建立唯一 `ExecutionGateway`。其他真实执行入口仅可调用该网关；不能提供完整审阅材料的入口只可做 dry-run/提议或拒绝。
- 为 ticket 设计不可变身份、有效期、单次/幂等消费策略与撤销/过期状态；把现有一致性模型的字段作为契约基础而不是重复一套字段。
- 修改 Pipeline Runtime 的公开调用形态，使其需要经过验证的 execution context/ticket；内部低层测试可使用显式受限的测试构造器，生产入口不可绕过。

**完成定义**：见 [任务 7A](任务7A_执行入口收敛与执行票据.md)。

### Phase 7B：运行时能力与路径强制（P0，依赖 7A）

**交付**：`ToolExecutionContext`、统一路径与节点/后端权限检查、Runner 前强制点、外部进程调用的同一约束面。

- 把 `ToolSpec.allowed_read_paths` / `allowed_write_paths` 从描述元数据升级为相对于 ticket 根目录求值的可执行策略；拒绝绝对路径漂移、`..`、符号链接逃逸、未声明输出、rawdata 写入和未批准外部后端。
- 扩展或组合现有 `NodeExecutionContext`，使每个 Runner 获得只读的 ticket/capability 视图；所有文件与外部进程操作使用该视图，而不是从任意 node params 或配置重复推导授权。
- 在 node runner 分发点一次性执行 node-id、backend、输入、输出、路径、过期和审计关联检查；禁止通过在路由或 service 复制检查绕过 protected runtime。
- 对纯 Python、native preprocessing、SPM、DPABI、GPU、DICOM 分别建立明确的允许/拒绝测试；外部执行仍须经过既有环境门控和人工审批。

**完成定义**：见 [任务 7B](任务7B_运行时能力与路径强制.md)。

### Phase 7C：统一状态机、观察与受控恢复（依赖 7A/7B）

**交付**：单一 Agent 生命周期记录、合法迁移器、观察结论、受限 retry/replan 决策与前端/API 可查询状态。

- 实现 `CREATED → CONTEXT_READY → PLAN_DRAFTED → PLAN_VALIDATED → WAITING_FOR_APPROVAL → APPROVED → EXECUTION_READY → RUNNING → OBSERVING → SUCCEEDED`，以及 `FAILED → DIAGNOSING → RETRY_PROPOSED → WAITING_FOR_RETRY_APPROVAL → RETRYING → SUCCEEDED/HUMAN_HANDOFF` 分支。
- 状态迁移由后端 orchestrator 发起并原子持久化；前端和旧路由只能请求意图，不能自行决定下一个执行 API。
- 观察步骤只判断产物、运行状态、科学验证结果和票据范围；无法证明成功时返回 `partial`、`needs_review` 或 `human_handoff`，不得虚报 `succeeded`。
- 仅允许 ticket retry policy 中明确允许且未达配额的低风险重试；任何重规划、参数/节点/后端/路径变化都生成新 plan 并回到验证和审批。

**完成定义**：见 [任务 7C](任务7C_统一状态机与受控恢复.md)。

### Phase 7D：节点契约与结构化规划（依赖 7A/7B）

**交付**：节点输入/参数/输出/前后置条件/副作用/资源/重试/幂等/验证策略的可验证注册契约；由契约驱动的 Validator；受约束的 Planner 输出。

- 为节点注册表引入版本化 `NodeContract`，先覆盖当前可执行且 allowlist 中的节点；未覆盖节点不得被新 Planner 标为可执行。
- Validator 在审批前验证每个节点参数和跨节点数据契约，不仅检查 `params` 是字典。需要规范化后的参数哈希进入 reviewed plan/ticket。
- Planner 保持 LLM 仅作候选计划生成者；调用 provider 时使用严格 schema/解析边界，失败时报告结构化错误，不回退为看似成功的自由文本计划。
- 先实现候选计划的解释、置信度与“需要人工补充”结果；多候选排序、长期记忆推荐和自动重规划须在评测集证明安全收益后再进入后续阶段。

**完成定义**：见 [任务 7D](任务7D_节点契约与结构化规划.md)。

## 6. Hazards & Mitigations

| H-ID | 风险 | 缓解措施 | 验证 |
|---|---|---|---|
| H-01 | 兼容入口继续绕过审阅执行 | 入口清单；旧入口 410 或仅调用网关；CI 禁止公开路由直接调用 Runtime | AST/grep 守卫 + API 回归 |
| H-02 | 票据可由客户端伪造或跨项目复用 | 服务端签发、持久化身份、项目/哈希/审批/allowlist/有效期绑定 | 篡改、跨项目、过期、重复消费测试 |
| H-03 | 路径检查停留在元数据 | Runner 前的 canonical path enforcement；拒绝 `..`、绝对漂移、链接逃逸和 rawdata 写入 | 临时目录、symlink、越界读写测试 |
| H-04 | 外部工具在迁移时被意外打开 | 默认拒绝，保留已有 env/approval/审计 gates；外部后端分组测试 | 未配置环境和未批准请求均拒绝 |
| H-05 | Runtime 改造破坏既有科学链路 | 先以纯 Python 合成 fixture 迁移；保留产物/状态回归并逐类迁移外部后端 | focused + affected-layer suite |
| H-06 | 状态机把诊断建议误变自动执行 | retry 仅由状态机按 ticket policy 触发；默认人工审批 | 非法迁移、配额、重规划审批测试 |
| H-07 | 节点参数 schema 与遗留计划不兼容 | 显式版本、适配器、弃用窗口和迁移测试；未知契约 fail-closed | legacy fixture + migration tests |
| H-08 | 长期记忆泄露 PHI 或机器路径 | 阶段八前不写入；设计必须最小化、脱敏、可撤销、可审阅 | 安全评审后再实现 |

## 8. Proof Obligations

| 声明 | 证明方式 |
|---|---|
| 任何真实执行都经唯一网关 | 枚举 API route → service → Runtime 调用图；CI 禁止公开路由直接 import/call `run_pipeline` |
| ticket 与获批计划不可漂移 | 对 ticket 和 reviewed/dry-run/execution 三快照做一致性测试；篡改任一绑定字段必须拒绝 |
| 路径许可在实际访问前生效 | 在 runner dispatch 前断言 capability；用越界/链接 fixture 验证没有 runner 被调用 |
| external execution 仍默认关闭 | 未设置环境门控、未具备 approval 或 ticket backend 许可时，断言无 subprocess 调用 |
| 状态不会被前端或诊断模块跳转 | 只公开 command API；非法 transition 单测与持久化审计 |
| 科学成功声明仍真实 | 对已有数值产物运行 reload/shape/dtype/provenance 回归；不把 dry-run/metadata 标为 computed |
