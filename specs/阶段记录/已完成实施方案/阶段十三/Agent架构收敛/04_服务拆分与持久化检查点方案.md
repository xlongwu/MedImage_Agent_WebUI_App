# 阶段四：服务拆分与持久化检查点方案

> 归档状态：该文档对应的当前阶段范围已完成；仅作为历史实施与审计记录保留。

> 状态：已实施并通过最终集成审查
> 依赖：阶段三完成
> 本阶段重排服务职责和事务边界，不改变公共任务状态含义。

## 1. 目标

缩小 `AgentTaskCommandService` 和 `AgentHarnessService` 的职责，明确每次可能中断的位置。进程重启、重复唤醒或工作进程接管后，系统从数据库继续，而不是依赖内存回调。

## 2. 当前问题

- `AgentTaskCommandService` 同时处理创建、目标更新、科学回答、规划、审批、执行、取消、恢复、记忆和后台监控，构造依赖过多。
- 构造过程中会直接创建配置或记忆相关对象，测试和运行时依赖边界不清楚。
- `AgentHarnessService` 同时管理租约、预算、模型服务、动作校验、业务应用、回退、结束判断和回放。
- 模型调用记录已经先于网络写入，但“状态变更后必须唤醒”“动作接受后如何恢复”等业务检查点没有统一规则。

## 3. 目标服务划分

### 3.1 `AgentTaskCommandService`

保留为薄入口，只负责：

- 接收创建、回答、审批、取消命令。
- 校验命令 ID 的幂等性。
- 调用一个对应的领域服务。
- 返回后端权威投影。

它不直接构造配置、记忆存储、模型服务或后台调度器。

### 3.2 `AgentPlanningService`

负责：

- 创建后的目标分析。
- 应用科学回答。
- 构建规划上下文。
- 调用受控循环或确定性规划器。
- 持久化 `PendingDecisionBatch`、审阅计划和审批摘要。
- 计算下一次是否需要规划唤醒。

公开入口限制为 `advance_planning()` 和当前命令所需的少量方法。不得注入执行网关、节点执行器或执行票据服务。

### 3.3 `AgentApprovalExecutionService`

负责：

- 校验审批摘要、操作人、范围和哈希。
- 审批后运行试执行。
- 创建执行票据。
- 经唯一执行网关分派。

后台调度器和受控循环不得依赖该服务。

### 3.4 `AgentRecoveryCommandService`

负责：

- 取消命令的状态机规则。
- 用户确认后的恢复命令。
- 子票据相关的确定性服务编排。

观察、目标评估和恢复建议仍走专用只读投影，不塞回命令服务。

### 3.5 `AgentHarnessCoordinator`

从当前 `AgentHarnessService` 中保留：

- 尝试、步骤和租约的推进。
- 预算检查。
- 模型服务调用协调。
- 调用阶段二的 `AgentPlanningActionService`。

上下文由阶段三服务提供；`Trace` 和 `Replay` 保持独立只读服务。

### 3.6 `AgentTaskScheduler`

新增 `src/backend/app/services/agent_task_scheduler.py`，替换当前命令服务和协调器中的内存唤醒回调：

- `enqueue()` 只写或通知已经落库的唤醒记录。
- `claim_next()` 按任务 ID 和步骤键占用一条唤醒记录。
- `run_once()` 只调用 `AgentPlanningService.advance_planning()`。
- `rescan()` 只扫描可继续规划且没有有效租约的任务。
- `shutdown()` 停止接收新工作，等待当前有界步骤结束，不修改任务结果。

删除或收敛 `AgentTaskCommandService._wake_harness()`、`AgentTaskReconciler._wake_harness()` 和重复唤醒判断。协调器继续负责运行终态后的确定性状态协调，但不作为第二个后台规划所有者。

## 4. 依赖组装

在 FastAPI 依赖组装位置统一创建服务：

```text
ConfigService / Store / Provider / MemoryRepository
  -> ContextService / PlanningActionService / TicketService
  -> PlanningService / ApprovalExecutionService / RecoveryCommandService
  -> AgentTaskCommandService
```

禁止在服务构造函数内调用 `ConfigService()`、打开 SQLite 或根据环境变量选择模型服务。所有可变依赖由应用启动时组装并显式注入。

测试通过依赖替换或临时 SQLite 传入假实现。

## 5. 持久化检查点

本阶段使用现有 SQLite 权威状态和事务发件箱，不新增第二套事件数据库。

### 5.1 检查点表

| 检查点 | 同一事务内必须写入 | 事务提交后动作 | 恢复依据 |
|---|---|---|---|
| 创建任务 | 任务生命周期、创建命令、规划唤醒发件箱 | 调度器消费唤醒 | 有未完成任务且无有效租约 |
| 回答决定 | 回答、决定批次已消费、状态、规划唤醒发件箱 | 调度器继续规划 | 状态和批次版本 |
| 模型调用开始 | `ModelCallRecord(started)`、步骤占用记录 | 模型服务调用 | 开始记录和租约 |
| 模型响应通过 | 已完成调用、`AgentActionRecord(accepted)` | 应用动作 | 已接受但未完成的动作 |
| 动作完成 | 业务状态、动作完成记录、下一唤醒发件箱 | 调度器或等待用户 | 任务状态和动作 ID |
| 审批通过 | 审批记录、状态 | 试执行 | 审批摘要哈希、命令 ID |
| 分派前 | 已签发票据、分派意图 | 执行网关 | 未消费票据和分派意图 |

### 5.2 事务发件箱规则

- 任何“状态写完后需要后台继续”的命令，都必须在同一数据库事务中写入唤醒发件箱。
- 内存队列只负责加速，不是权威来源。
- 调度器成功占用任务后再标记发件箱已消费；处理失败按有界退避重试。
- 启动时扫描未消费发件箱、过期租约和可继续状态。
- 重复唤醒通过任务状态、步骤键、动作 ID 和命令 ID 去重。

### 5.3 中断恢复规则

- `ModelCallRecord(started, network_called=false)`：允许新工作进程重新开始该次调用。
- `network_called=true` 且无响应：不得盲目重试同一次调用；按模型服务的幂等能力决定新调用或人工接管，并记录原因。
- `AgentActionRecord(accepted)` 但未完成：使用动作哈希和预期状态重放本地确定性应用，不重新调用模型。
- 审阅计划已持久化但唤醒未消费：只重建审批摘要，不重复生成计划。
- 执行票据已签发但未分派：由执行网关使用票据幂等键继续，不创建第二张票据。

## 6. 实施步骤

1. 先为当前创建、回答、审批、取消和受控循环步骤行为补特征测试。
2. 抽出只读依赖接口和服务构造，不改变状态迁移。
3. 抽出 `AgentPlanningService`，让调度器只能看到该服务。
4. 抽出 `AgentApprovalExecutionService` 和 `AgentRecoveryCommandService`。
5. 把 Harness 业务动作移交给阶段二服务。
6. 新增 `AgentTaskScheduler`，切换命令服务和协调器的唤醒调用。
7. 增加事务发件箱和动作恢复逻辑。
8. 删除旧私有方法、构造期依赖创建和重复状态判断。
9. 全仓搜索旧方法和直接存储调用，确认消费者已切换。

不要一次重写整个文件。每抽出一个服务就运行对应特征测试，并对照当前状态机。

## 7. 风险和处理

| 编号 | 风险 | 处理 | 证明方式 |
|---|---|---|---|
| H-05 | 拆分时出现两个任务状态所有者 | 命令入口仍由 `AgentTaskCommandService` 串联，每次迁移一个方法 | 并发命令和调用顺序测试 |
| H-05A | 调度器间接拿到执行能力 | `AgentPlanningService` 依赖图不含执行服务 | 构造和调用检查测试 |
| H-06 | 状态提交后唤醒丢失 | 状态与事务发件箱同事务 | 终止、重启和队列满测试 |
| H-06A | 中断后重复调用模型 | 步骤占用、调用记录和恢复表共同判断 | 每个中断点故障注入 |
| H-06B | 自动修复掩盖损坏状态 | 恢复只处理已定义状态，其他情况转人工处理 | 未知组合安全拒绝测试 |

## 8. 测试

必须覆盖：

1. 创建、回答、审批、取消的公共响应和状态迁移不变。
2. 相同命令 ID 重放不产生第二个决定、计划、审批或执行。
3. 两个调度器同时占用任务时只有一个成功。
4. 队列满、唤醒丢失、服务重启和租约过期后最终继续。
5. 每个检查点前后中断，恢复结果符合本方案表格。
6. 已接受动作的本地重放不调用模型服务。
7. 调度器的依赖无法到达试执行、执行票据、执行网关和节点执行器。
8. GET/list 不消费事务发件箱、不触发状态协调、不调用模型。
9. 仅规划仍然不创建执行审批、执行票据、运行记录或数值产物。

```powershell
python -m pytest tests/unit/test_agent_task_commands.py tests/unit/test_agent_planning_service.py tests/unit/test_agent_task_reconciler.py tests/unit/test_agent_harness_service.py tests/unit/test_agent_harness_lease.py --tb=short --basetemp=.pytest_tmp
python -m pytest tests/integration/test_agent_harness_lifecycle.py --tb=short --basetemp=.pytest_tmp
```

## 10. 退出条件

- `AgentTaskCommandService` 只保留命令入口和投影返回。
- `AgentHarnessService` 不再直接实现业务动作、上下文压缩或恢复。
- 依赖图和测试证明调度器不可达执行边界。
- 并发、重启、中断和重复命令测试全部通过。
