# 阶段三：模型上下文与证据读取优化方案

> 归档状态：该文档对应的当前阶段范围已完成；仅作为历史实施与审计记录保留。

> 状态：已实施并通过最终集成审查
> 依赖：阶段二完成
> 本阶段只改变模型可见信息的选择和完整性检查，不新增模型权限。

## 1. 目标

每次模型调用只读取当前动作需要的信息。长度不足时优先压缩可选说明，不能静默删除生成决定或计划所必需的证据。

## 2. 当前问题

`AgentHarnessContextService` 当前按固定的十个信息段生成上下文，并用 `MAX_BYTES = 32 * 1024` 限制大小。超限时会删除整段可选信息。这样虽然能控制输入长度，但模型无法知道被删内容是否影响当前规划。

本项目保存的是结构化任务和证据，不需要照搬通用聊天系统的完整对话压缩、磁盘溢写或任意历史检索。

## 3. 上下文分为两种用途

新增 `AgentContextPurpose`：

```python
AgentContextPurpose = Literal[
    "decision_request",
    "plan_draft",
]
```

### 3.1 `decision_request`

必须包含：

- 当前目标合同和版本。
- 已确认的科学回答。
- 未解决的科学缺口及其来源。
- 与缺口直接相关的项目证据引用。
- 当前任务生命周期状态和允许动作。

不得包含：

- 完整运行日志。
- 与缺口无关的历史任务。
- 原始图像、`rawdata` 内容和未登记路径。
- 审批摘要、执行票据或执行能力对象。

### 3.2 `plan_draft`

必须包含：

- 目标合同、科学回答和版本。
- 已确认的 BIDS/项目证据摘要及引用。
- 工具目录中当前允许规划的节点和后端。
- 安全写入根、`rawdata` 只读规则和仅规划标记。
- 当前审阅计划的父版本信息，若本次是重规划。

不得包含：

- 审批令牌、执行票据、模型服务凭据。
- 未经登记的文件内容。
- 无关任务的记忆或日志。

## 4. 修改 `AgentHarnessContext`

在现有数据结构上增加：

- `purpose`
- `required_sections`
- `included_sections`
- `omitted_sections`
- `evidence_refs`
- `evidence_snapshot_hash`
- `projection_policy_version`
- `complete`
- `incomplete_reason`

`context_hash` 必须覆盖以上字段、实际发送的信息段、工具目录版本、`MemoryContext` 哈希和提示词版本。

`complete=false` 的上下文不得发给模型服务。

## 5. 修改构建流程

把单一构建流程拆成明确步骤：

```text
根据任务生命周期状态确定用途
-> 列出必需信息段
-> 从存储读取结构化记录和带类型引用
-> 检查引用存在、项目一致且版本匹配
-> 先生成必要信息段
-> 再按固定顺序加入可选信息段
-> 超限时压缩可选信息段
-> 仍超限则返回结构化错误
-> 计算 context_hash
```

新增 `AgentContextProjectionPolicy`，只保存明确规则，不提供任意配置脚本。建议包含：

- 每种用途的必需信息段列表。
- 可选信息段的加入顺序。
- 每个信息段的最大条数和最大字节数。
- 结构化摘要版本。

## 6. 长度处理规则

按以下顺序缩减：

1. 去掉重复的人类可读说明，保留结构化字段和引用。
2. 对可选历史记录只保留最近且与当前目标直接相关的固定数量。
3. 对证据只保留已登记摘要、校验状态、哈希和带类型引用，不读取大文件正文。
4. 删除可选信息段，并在 `omitted_sections` 中记录原因。
5. 必需信息段仍超限时返回 `AGENT_CONTEXT_REQUIRED_SECTION_TOO_LARGE`，不得继续调用模型。

禁止使用“截断到刚好 32 KiB”的字符串切片，因为这可能生成不完整 JSON 或丢失字段含义。

## 7. 证据读取规则

- 只通过 `ProjectStore`、产物服务和现有证据服务读取。
- 每个引用必须包含类型、记录 ID、版本或哈希，不使用任意路径字符串。
- 读取前检查引用属于当前 `project_id`。
- 证据状态不是已验证时，在信息段中明确标记，不得写成已确认事实。
- 对缺失、过期或哈希不匹配的必需证据返回结构化错误。
- 记忆只作为建议背景；缺少记忆不阻止规划，且不能提供审批或当前环境事实。

## 8. 需要修改的文件

| 文件 | 修改内容 |

## 9. 风险和处理

| 编号 | 风险 | 处理 | 证明方式 |
|---|---|---|---|
| H-04 | 必要证据被当作可选项删除 | 每种用途固定必需信息段 | 每种用途的缺失测试 |
| H-04A | 上下文缩减后哈希不变 | 哈希直接覆盖最终内容和信息段清单 | 修改任一信息段即改变哈希 |
| H-04B | 证据引用跨项目 | 读取时校验 `project_id` | 跨项目引用拒绝测试 |
| H-04C | 为减少长度读取原始文件摘要 | 只消费已登记结构化摘要 | 调用检查证明 `rawdata` 文件未打开 |
| H-04D | 可选记忆被当成当前事实 | 单独标记来源和建议性质 | 提示词样例和合同测试 |

## 10. 测试

必须覆盖：

1. 两种用途的必需和禁止信息段。
2. 必需信息段缺失、过期、跨项目和哈希不匹配时模型服务零调用。
3. 可选信息段超限时按固定顺序删除，并记录 `omitted_sections`。
4. 必需信息段超限时返回结构化错误，不做字符串截断。
5. 相同输入得到相同上下文内容和哈希。
6. 目标、科学回答、证据引用、工具目录、记忆或规则版本改变时哈希改变。
7. 上下文和 `Trace` 中没有 `rawdata` 内容、凭据和绝对研究数据路径。

推荐命令：

```powershell
python -m pytest tests/unit/test_agent_harness_context.py tests/unit/test_agent_harness_service.py tests/unit/test_agent_evidence_context.py --tb=short --basetemp=.pytest_tmp
```

其中 `test_agent_evidence_context.py` 是本阶段需要新增的针对性测试，不能从命令中删除该验证范围。
