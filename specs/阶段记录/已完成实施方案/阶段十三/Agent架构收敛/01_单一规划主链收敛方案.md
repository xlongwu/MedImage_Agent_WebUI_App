# 阶段一：单一规划主链收敛方案

> 归档状态：该文档对应的当前阶段范围已完成；仅作为历史实施与审计记录保留。

> 状态：已实施并通过最终集成审查
> 依赖：无
> 本阶段只处理入口和消费者迁移，不修改模型动作、审批和执行语义。

## 1. 目标

删除旧的 `/api/agent/plan`、`/api/agent-runs/{agent_run_id}` 和 `outputs/work/agent_runs` 文件型流程。用户目标统一通过 Agent 任务接口创建、查询、回答、审批和取消。

## 2. 当前问题

当前同时存在两套规划路径：

```text
旧路径：/api/agent/plan -> run_orchestrator_plan() -> create_agent_plan() -> outputs/work/agent_runs
主路径：Agent 任务接口 -> AgentTaskCommandService -> 审阅计划 -> 审批摘要
```

旧路径没有完整接入当前任务生命周期、决定批次、审批摘要、模型调用账本和重启恢复。继续保留会导致相同目标在不同入口得到不同状态和证据。

## 3. 详细修改

### 3.1 先列出全部当前消费者

实施前用以下搜索生成清单，并把结果加入该阶段的评审说明：

```powershell
rg -n "/api/agent/plan|/api/agent-runs|run_orchestrator_plan|create_agent_plan|outputs/work.*agent_runs|pipeline\.plan|pipeline\.execute" src tests docs README.md README_CN.md
```

至少检查：

- `src/frontend/src/lib/api/pipeline.ts`
- `src/backend/app/tools/api_smoke_test.py`
- `src/backend/app/runtime/agent_runtime.py`
- `src/backend/app/runtime/agent_plan.py`
- `src/backend/app/runtime/tool_registry.py`
- Agent 相关命令行入口
- `tests/unit/test_backend_infrastructure.py` 及旧规划测试
- README、架构文档和 API 文档

### 3.2 迁移前端调用

修改 `src/frontend/src/lib/api/pipeline.ts`：

1. 删除调用 `/api/agent/plan` 的函数。
2. 删除读取 `/api/agent-runs/{id}` 的函数和只服务于旧返回值的类型。
3. 当前仍需要“创建 Agent 任务”的页面统一调用 `src/frontend/src/lib/api/agentTasks.ts`。
4. 当前仍需要“查看运行”的页面统一读取项目 `/runs` 和 Agent 任务详情，不再读取 `plan.json`、`agent_summary.json` 或 `review_summary.md`。
5. 删除无消费者的导出，更新 mock 和前端测试。

不在 `agentTasks.ts` 中增加兼容函数，也不把旧响应转换成新响应。

### 3.3 迁移命令行和 smoke test

对于仍在使用的命令行入口，改为以下流程：

```text
创建 Agent 任务
-> 轮询任务投影
-> 如需决定则提交 answer
-> 到 WAITING_FOR_APPROVAL 后停止
```

命令行不得自动审批。只用于旧文件型规划且没有当前用户入口的脚本直接删除。

`src/backend/app/tools/api_smoke_test.py` 改为检查 Agent 任务的创建、详情和仅规划路径，不再构造固定 `agent_run_001`。

### 3.4 拆分 `agent_routes.py`

`src/backend/app/api/agent_routes.py` 还包含 `/api/runs`、重试和调度等非 Agent 任务路由，不能整文件删除。按现有领域路由规则处理：

1. 把 `/api/runs` 和 run detail 移到现有 Runs router；没有合适 router 时新增 `run_routes.py`。
2. 把 retry 路由移到 `retry_routes.py`。
3. 把调度路由移到 `scheduler_routes.py`。
4. 在 `create_app()` 中注册新 router。
5. 当前消费者全部切换后，删除 `agent_plan()`、`get_agent_run()`、旧 `_read_json_if_exists()` 和 `_read_text_if_exists()`。
6. 若 `agent_routes.py` 不再有职责，删除该文件和注册项。

路由只做请求接收、依赖注入和结构化错误映射。迁移时不得把旧文件读取逻辑搬到新路由。

### 3.5 删除旧运行时

确认无当前消费者后删除：

- `src/backend/app/runtime/agent_runtime.py`
- `src/backend/app/runtime/agent_plan.py`
- 只为旧 Agent 规划服务的 tool registry 项和类型
- 只验证旧路径的测试样例和测试

若 `runtime/tool_registry.py` 还有其他消费者，只删除 `pipeline.plan`、`pipeline.execute` 及对应未使用代码，不删除整个文件。

### 3.6 更新文档

更新以下文档中的入口和调用链：

- `README.md`
- `README_CN.md`
- `docs/架构与决策/系统架构.md`
- `docs/规划与运行时/受控单AgentHarness.md`
- `docs/文档索引.md`
- 当前仍引用旧 API 或 `outputs/work/agent_runs` 的阶段文档

历史阶段记录可保留历史描述，但必须明确标注为历史行为，不能继续作为当前使用说明。

## 4. 数据和接口变化

本阶段删除旧接口，不增加替代兼容字段。Agent 任务现有数据结构是唯一公共合同。

删除前必须确认：

- 前端没有旧函数导入。
- 后端没有旧 runtime 导入。
- 测试没有把旧 API 当作基础设施必需项。
- 文档没有把旧 API 写成当前入口。
- 项目启动不会创建 `outputs/work/agent_runs`。

## 5. 风险和处理

| 编号 | 风险 | 处理 | 证明方式 |
|---|---|---|---|
| H-01 | 删除旧入口后某个页面无法规划 | 先迁移并测试全部当前消费者，再删除生产代码 | 全仓引用搜索为零，前端调用测试通过 |
| H-01A | 把 `/api/runs` 一并误删 | 先按领域拆路由，再删旧 Agent 路由 | Runs 接口合同测试 |
| H-01B | 旧命令行被悄悄改成自动审批 | 命令行只推进到等待审批 | 调用检查证明审批函数未调用 |
| H-01C | 用户已有文件型记录无法在新页面打开 | 不增加旧格式读取；在变更说明中明确一次性切换 | 旧格式 fail-closed 测试 |
