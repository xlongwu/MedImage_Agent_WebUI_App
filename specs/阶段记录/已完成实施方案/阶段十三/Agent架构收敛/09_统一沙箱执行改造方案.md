# 统一沙箱执行改造方案

> 归档状态：该文档对应的当前阶段范围已完成；仅作为历史实施与审计记录保留。

> 状态：已实施并通过源码及打包后 Windows 沙箱验收
> 任务模式：架构调整与安全加固
> 建议排期：阶段五“执行环境快照与票据绑定”完成后单独实施
> 本方案不会开放 MATLAB、SPM、DPABI、GPU 或任意外部命令。

## 1. 目标

本方案把“沙箱”定义为：为一次节点执行创建独立工作目录，并用受限制的子进程运行外部程序。子进程只能写入本次工作目录，不能写 rawdata、项目外目录或系统目录。

改造完成后必须达到以下结果：

1. 实际执行仍然只能从 `ExecutionGateway.dispatch()` 进入。
2. 旧的 `execute-sandbox` 接口和散落的 `subprocess.run()` 不能形成第二条执行路径。
3. 外部程序只能使用审批时绑定的可执行文件，调用方不能传入程序路径。
4. 每次执行都有独立的输入副本、输出目录、日志目录、临时目录和状态记录。
5. 超时、取消或后端退出时，必须结束该次执行创建的完整进程树。
6. 只有通过路径、文件和科学产物检查的结果才能登记为 Artifact。
7. 不能实现的隔离能力必须明确显示为“未提供”，不得以目录复制冒充系统隔离。

## 2. 当前结论

当前项目已经有审批、执行票据、唯一执行网关和节点读写范围检查，这些能力继续保留。

当前名称中带有 `sandbox` 的旧实现主要是“复制输入后调用 `subprocess.run()`”。子进程仍使用后端进程的用户权限，因此可以访问当前用户原本能够访问的其他目录。它不是完整沙箱，不能直接重新开放。

当前公共 `execute-sandbox` 接口已经通过 `reject_execution_contract()` 返回 `410`，外部 MATLAB/SPM/DPABI 节点也已由阻断函数替换。本方案先删除这些已失效入口，再建立一套只能由执行网关调用的新实现。

## 4. 范围与非目标

### 4.1 本次必须完成

- 删除已失效的公开 `execute-sandbox` 路由、前端封装和只被旧入口使用的服务。
- 盘点应用运行时中的全部 `subprocess` 调用，按“删除、保留为开发工具、迁入统一沙箱”分类。
- 新增沙箱策略、执行记录、工作目录和进程运行结果的数据结构。
- 把沙箱策略哈希绑定到 Reviewed Plan 审批摘要、执行环境快照和 Execution Ticket。
- 在 Windows 上实现受限制进程、完整进程树控制、超时和资源限制。
- 外部进程只接收经过筛选的环境变量和沙箱内路径。
- 对输出执行路径、文件、哈希和可重载检查，通过后再登记产物。
- 增加沙箱状态只读接口和运行详情展示。
- 补齐单元、集成、API、桌面打包和人工验收。

### 4.2 本次明确不做

- 不启用任何当前 `executable=false` 的 MATLAB/SPM/DPABI/GPU 节点。
- 不让 LLM、Route 或前端直接创建沙箱、启动进程或传入命令。
- 不迁移 `native_preproc_full_execute` 等原生 Python 科学计算到子进程。
- 不引入 Docker、WSL、虚拟机或远程执行服务。
- 不承诺网络隔离；首期响应中明确返回 `network_isolation="not_enforced"`。
- 不保留旧 `execute-sandbox` 接口、旧请求结构或兼容读取。
- 不通过修改文件权限、扩大 ACL 或关闭安全软件来绕过启动失败。

原生 Python 科学计算仍由现有 Pipeline Runtime 执行，继续受执行票据、节点合同和路径检查约束。以后若要把它迁入独立进程，必须单独处理 SQLite 存储依赖、科学数据传递和恢复语义，不混入本方案。

## 5. 目标调用链

```text
Reviewed Plan
  -> 捕获执行环境快照
  -> 纯计算生成沙箱策略集合
  -> 持久化绑定策略哈希的 Approval Summary
  -> 用户审批
  -> 审批后 dry-run
  -> 创建并持久化包含已批准策略的 Execution Ticket
  -> ExecutionGateway 校验票据和执行环境
  -> SandboxWorkspaceService.prepare()
  -> SandboxProcessRunner.run()
  -> SandboxOutputVerifier.verify()
  -> 原子提升到批准的 derivatives/reports/logs
  -> Artifact 注册
  -> 写入沙箱终态和 Gateway 结果
```

顺序要求：

1. 规划阶段不能创建目录、复制输入或启动进程。
2. `SandboxPolicyService.build_for_plan()` 可以在审批前纯计算策略，但不能创建执行沙箱。
3. Approval Summary 必须包含策略摘要和稳定哈希，用户审批的是该固定策略。
4. 审批后的 dry-run 只能复验参数、路径、容量和策略，不启动外部程序。
5. 网关完成票据、策略和环境复验后，才能创建工作目录。
6. 工作目录准备失败时不能消费票据，也不能调用节点执行函数。
7. 进程启动前必须先持久化 `sandbox_prepared`。
8. 进程终态和输出检查结果必须先落库，再向调用方报告完成。

## 6. 沙箱目录

每次外部节点尝试使用一个独立目录：

```text
<project_work>/sandboxes/<run_id>/<node_id>/<attempt_id>/
  staged_input/     外部程序实际读取的输入副本
  output/           等待检查的输出
  logs/             stdout.log、stderr.log
  tmp/              本次执行专用临时目录
  meta/             policy.json、request.json、result.json
```

目录规则：

- `project_work` 必须来自已持久化项目配置和 Ticket 的批准写入根。
- `run_id`、`node_id`、`attempt_id` 必须先校验为安全 ID，不能包含路径分隔符。
- `attempt_id` 由后端生成，不能由接口请求指定。
- 不创建符号链接、Junction 或硬链接。
- 输入使用普通文件复制，并在复制前后比较 SHA-256。
- 外部脚本只能引用 `staged_input/`、`output/`、`logs/` 和 `tmp/`。
- 原始 rawdata 绝对路径不能出现在脚本、命令参数、日志摘要或对外响应中。
- `output/` 中的内容检查通过前不能移动到项目正式产物目录。

MATLAB/SPM 可能在输入文件旁生成带前缀的新文件，因此 `staged_input/` 是可写副本。写入该目录不会影响 rawdata 或登记输入；最终只提取节点合同声明的输出。

## 8. 后端修改方法

### 8.1 新增 `SandboxPolicyService`

文件：`src/backend/app/services/sandbox_policy_service.py`

公开方法：

```python
def build_for_plan(
    self,
    *,
    reviewed_plan: ReviewedPlanRecord,
    environment: ExecutionEnvironmentSnapshot,
    write_roots: tuple[str, ...],
    readonly_roots: tuple[str, ...],
) -> SandboxPolicySet: ...
```

处理步骤：

1. 只读取审阅计划中 `NodeContract.resources.process_mode="sandbox_process"` 的节点。
2. 从执行环境快照取得已解析程序 ID 和路径哈希。
3. 从节点合同取得后端、允许的输入输出类型和资源限制。
4. 使用固定环境变量白名单生成策略。
5. 对排序后的策略内容计算 `policy_hash` 和 `policies_hash`。
6. 发现未知节点、缺失程序、缺失限制或非 Windows 执行实现时直接阻断。

该方法不能读取 `os.environ`、创建目录、调用程序或修改数据库。实际环境信息统一由 `ExecutionEnvironmentService` 提供。生成结果在等待审批前进入 Approval Summary；审批后只允许重建并比较，不允许静默改变。

### 8.2 新增 `SandboxWorkspaceService`

文件：`src/backend/app/services/sandbox_workspace_service.py`

公开方法：

```python
def prepare(... ) -> SandboxAttemptRecord: ...
def stage_inputs(... ) -> InputManifest: ...
def mark_running(... ) -> SandboxAttemptRecord: ...
def finalize(... ) -> SandboxAttemptRecord: ...
def cleanup_terminal_attempt(... ) -> None: ...
```

具体要求：

- `attempt_id` 使用 `dispatch_id`、node、subject 和重试序号的稳定哈希生成，不使用随机值。
- `sandbox_id` 使用 Ticket、run、node、subject 和 `attempt_id` 的稳定哈希生成。
- 重放同一命令时复用同一目录；策略哈希不同则返回 `SANDBOX_IDENTITY_CONFLICT`。
- 所有 JSON 使用 `atomic_write_json()` 并带 `_schema_version`。
- `stage_inputs()` 只接收已经由 Artifact 服务或 Reviewed Plan 解析出的文件，不接收任意目录。
- 复制前后校验大小和 SHA-256；校验失败删除本次不完整副本并阻断。
- 删除前必须确认目标是 `sandboxes/<run_id>/<node_id>/<attempt_id>` 的直接预期目录。
- 运行失败时默认保留证据；只在达到保留期且没有未完成调查标记时清理。

### 8.3 新增 Windows 进程控制

文件：

- `src/backend/app/runtime/sandbox_process_runner.py`
- `src/backend/app/runtime/windows_process_sandbox.py`

不新增 `pywin32` 依赖。项目已有 `ctypes` 使用方式，Windows API 封装继续使用标准库 `ctypes`，避免扩大桌面打包依赖。

`WindowsProcessSandbox` 必须按以下顺序启动：

1. 打开当前进程令牌。
2. 使用 `CreateRestrictedToken()` 删除不必要权限，并增加写入限制。
3. 使用暂停状态创建子进程。
4. 创建 Job Object。
5. 设置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`、内存限制和最大进程数。
6. 将子进程加入 Job Object。
7. 恢复子进程运行。
8. 等待完成、取消或超时。
9. 超时或取消时通过 Job Object 结束完整进程树。
10. 读取退出码并关闭全部句柄。

目录权限要求：

- `staged_input/`、`output/`、`logs/`、`tmp/` 只授予本次受限制进程需要的写权限。
- rawdata、登记输入、项目源码和其他项目目录不授予沙箱写权限。
- 权限设置失败时返回 `SANDBOX_ACL_SETUP_FAILED`，不得回退为普通 `subprocess.run()`。

进程请求要求：

- 固定 `shell=False`。
- `argv[0]` 必须与环境快照绑定的程序路径和哈希一致。
- 命令中不得包含 rawdata 原始路径。
- `cwd` 固定为本次沙箱目录。
- `TEMP`、`TMP` 指向本次 `tmp/`。
- 只保留 `SystemRoot`、工具运行必需项和策略明确允许的变量。
- 不传递 API Key、审批令牌、Cookie、数据库路径或完整父进程环境。
- 日志只写文件；数据库保存命令哈希和脱敏摘要，不保存完整命令。

Windows 官方实现参考：

- [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)
- [CreateRestrictedToken](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-createrestrictedtoken)

其他操作系统使用 `UnsupportedSandboxProcessRunner`，固定返回 `SANDBOX_PROVIDER_UNAVAILABLE`。不得自动改用普通 `subprocess.run()`。

### 8.4 修改 `ExecutionGateway`

文件：`src/backend/app/runtime/execution_gateway.py`

在 `dispatch()` 中增加：

1. 校验 Ticket 的 `sandbox_policies_hash`。
2. 使用 Ticket 中的完整策略集合重算哈希，防止内容被改写。
3. 通过 `ExecutionEnvironmentService.verify_for_dispatch()` 复验沙箱执行实现和实现哈希。
4. 调用新增的 `resolve_verified_executable()` 取得当前程序路径，并确认其哈希与策略一致。
5. 创建或复用当前 `GatewayDispatch` 记录，但不写 `dispatch_started`。
6. 使用 `dispatch_id` 计算本次节点尝试的稳定 `attempt_id` 和 `sandbox_id`。
7. 调用 `SandboxWorkspaceService.prepare()`。
8. 持久化 `sandbox_prepared` Gateway 事件。
9. 消费一次性 Ticket。
10. 持久化 `dispatch_started`。
11. 仅通过 `SandboxProcessRunner` 启动外部进程。
12. 把 `sandbox_id`、策略哈希和终态写入 Gateway 结果。

同步修改 `src/backend/app/schemas/gateway_dispatch.py`：

- `GatewayDispatch` 增加 `sandbox_policies_hash` 和 `sandbox_provider`，并纳入 `canonical_hash`。
- `GatewayDispatchEventType` 增加 `sandbox_prepared`。
- 只有 `sandbox_prepared`、尚无 `dispatch_started` 的重放可以继续准备；已有 `dispatch_started` 但没有终态时仍返回 `GATEWAY_DISPATCH_OUTCOME_UNKNOWN`。
- 准备失败写 `dispatch_rejected`，Ticket 保持未消费；修复环境后必须使用新的命令 ID 重试。

如果当前计划没有外部进程节点，`sandbox_policies_hash` 仍绑定一个固定空集合哈希，但不创建沙箱目录。

Gateway 的执行函数参数不能新增任意命令或调用方提供的环境变量。传给运行时的只能是服务端生成的 `SandboxExecutionContext`。`resolve_verified_executable()` 只在环境快照哈希复验成功后返回内部绝对路径，该路径不进入公共 API 或审计摘要。

### 8.5 修改 `ToolExecutionContext` 和节点合同

`src/backend/app/runtime/tool_execution_context.py` 增加：

```python
sandbox_policies: dict[str, SandboxPolicy]
```

`ResourceRequirements` 使用 `process_mode` 替换原有的 `external_process`：

```python
process_mode: Literal["in_process", "sandbox_process"]
```

同步更新全部创建方、读取方和测试，并删除 `external_process` 字段，不同时保留两个判断来源。

规则：

- 原生 Python 节点固定为 `in_process`。
- 任何会启动应用运行时外部程序的节点固定为 `sandbox_process`。
- 任何启动应用运行时外部程序的节点都必须声明为 `sandbox_process`。
- 节点执行函数不能根据参数自行降低隔离等级。

### 8.6 收口外部程序调用

所有应用运行时 `subprocess` 使用必须分类：

| 类型 | 处理方式 |
|---|---|
| 已删除公开入口专用执行代码 | 删除服务、数据结构、路由和测试 |
| 当前节点合同标记不可执行的 MATLAB/SPM/DPABI 节点执行函数 | 删除直接启动代码；只保留必要的纯计划或模板生成代码 |
| 审批后的真实外部节点 | 改为生成 `SandboxProcessRequest`，由统一进程运行器启动 |
| 审批前环境检查 | 只检查文件存在和配置，不启动外部程序 |
| 打包、构建和维护脚本 | 保留在应用运行时之外，并在盘点表中说明 |

实施时先运行：

```powershell
rg -n "subprocess\.(run|Popen|call|check_)" src/backend/app
```

分类表必须作为本阶段评审附件。应用运行时中除 `sandbox_process_runner.py` 外，不允许直接调用 `subprocess.run()` 或 `subprocess.Popen()`。增加源码级回归测试固定该规则。

`run_environment_check_node()` 必须改为读取 `ExecutionEnvironmentService` 的文件存在性和配置快照，不再调用 `run_matlab_check()`。如果以后需要实际启动 MATLAB 做探测，必须新增需要审批的沙箱节点，不能恢复审批前进程调用。

### 8.7 新增输出检查和提升

文件：`src/backend/app/services/sandbox_output_verifier.py`

公开方法：

```python
def verify_and_promote(
    self,
    *,
    attempt: SandboxAttemptRecord,
    contract: NodeContract,
    approved_output_roots: tuple[str, ...],
) -> VerifiedOutputManifest: ...
```

检查步骤：

1. 递归读取 `output/` 和允许产生输出的 `staged_input/`。
2. 拒绝符号链接、Junction、设备文件和指向目录外的路径。
3. 只接受节点合同声明的文件类型和相对位置。
4. 检查文件数量、单文件大小和总大小限制。
5. 计算 SHA-256。
6. NIfTI、JSON、CSV 等产物使用现有加载器重新打开。
7. 将文件复制到正式目录内的临时文件，再原子替换为最终文件。
8. 生成 `VerifiedOutputManifest`。
9. 完成后才调用 Artifact 注册服务。

正式目录必须使用唯一的 `run_id/node_id/attempt_id` 命名空间，默认不覆盖已有结果。发生同名冲突时返回 `SANDBOX_OUTPUT_ALREADY_EXISTS`，不能删除原结果重试。

### 8.8 持久化和中断恢复

在 `ProjectStore` Protocol 和 `SQLiteDesktopStore` 增加：

```python
def add_sandbox_attempt(...): ...
def get_sandbox_attempt(...): ...
def update_sandbox_attempt(...): ...
def list_sandbox_attempts_for_run(...): ...
```

新增 SQLite 表 `sandbox_attempts`，以 `sandbox_id` 唯一，`dispatch_id` 和 `execution_ticket_id` 建索引。

新增 `SandboxAttemptReconciler`：

- 后端启动时读取 `PREPARING`、`PREPARED`、`RUNNING` 记录。
- 当前所属后端进程已不存在且 Job Object 已关闭时，改为 `INTERRUPTED`。
- 不把中断记录自动改成成功或失败。
- 不自动重试或重新启动外部程序。
- 恢复执行必须走现有 recovery approval 和新 Ticket。

## 11. 错误码

新增结构化错误码：

| 错误码 | 含义 | 是否调用外部程序 |
|---|---|---|
| `SANDBOX_PROVIDER_UNAVAILABLE` | 当前系统没有受支持实现 | 否 |
| `EXECUTION_SANDBOX_POLICY_CHANGED` | 审批后沙箱实现或策略变化 | 否 |
| `SANDBOX_POLICY_MISSING` | 外部节点没有对应策略 | 否 |
| `SANDBOX_IDENTITY_CONFLICT` | 同一沙箱 ID 对应不同策略 | 否 |
| `SANDBOX_PATH_OUTSIDE_PROJECT` | 工作目录离开项目边界 | 否 |
| `SANDBOX_INPUT_NOT_APPROVED` | 输入不属于审阅计划或 Artifact | 否 |
| `SANDBOX_INPUT_COPY_MISMATCH` | 输入复制前后哈希不一致 | 否 |
| `SANDBOX_ACL_SETUP_FAILED` | 无法设置目录权限 | 否 |
| `SANDBOX_PROCESS_START_FAILED` | 受限进程启动失败 | 否 |
| `SANDBOX_PROCESS_TIMED_OUT` | 达到运行时间限制 | 是，进程树已终止 |
| `SANDBOX_PROCESS_TREE_TERMINATION_FAILED` | 无法确认进程树结束 | 是，运行标为阻断 |
| `SANDBOX_OUTPUT_UNSAFE` | 输出含越界路径或特殊文件 | 是，不登记产物 |
| `SANDBOX_OUTPUT_INVALID` | 输出无法重载或不符合合同 | 是，不登记产物 |
| `SANDBOX_OUTPUT_ALREADY_EXISTS` | 正式输出位置已有文件 | 是，不覆盖 |

错误响应只返回错误码、关联 ID 和安全摘要，不返回绝对路径和原始异常正文。

| 编号 | 风险 | 证据 | 处理 | 验证 |
|---|---|---|---|---|
| H-SBX-01 | 复制目录后直接启动进程被误认为系统隔离 | `preprocessing_spm_execution.py:188` | 删除旧执行服务，新进程必须使用受限制令牌和 Job Object | 旧服务引用为零；普通启动回退测试 |

| H-SBX-07 | 符号链接、Junction 或硬链接逃逸 | Windows 路径可使用重解析点 | 准备、运行后、登记前三次检查 | 符号链接和 Junction 参数化测试 |

## 13. 分阶段实施

### 阶段 A：删除旧入口并锁定现有行为

修改内容：

- 为当前 410 阻断行为、唯一 Gateway 和外部节点不可执行补特征测试。
- 生成应用运行时 `subprocess` 调用分类表。
- 将 `run_environment_check_node()` 改为只读取配置和文件存在性快照，并用调用记录测试证明它不会启动 MATLAB 或其他进程。
- 删除旧 `execute-sandbox` 路由、前端封装、重复服务和废弃测试。
- 增加 `test_runtime_subprocess_boundary.py`，禁止应用运行时新增直接进程调用，并把 `environment_check` 纳入检查范围。

退出条件：

- 所有执行请求只剩 Agent Task -> Approval -> Ticket -> Gateway 主链。
- 外部节点仍为不可执行。
- 全仓没有旧接口当前消费者。

### 阶段 B：增加沙箱合同和票据绑定

修改内容：

- 新增 `schemas/sandbox.py` 和 `SandboxPolicyService`。
- 更新 Approval Summary、环境快照、Execution Ticket 和 SQLite 格式。
- 将 `sandbox_policies_hash` 加入所有稳定哈希和审计记录。
- 增加空策略集合，保证纯原生计划不会创建目录。

退出条件：

- 相同计划和环境生成稳定相同的策略哈希。
- 策略或实现变化会在 Ticket 消费前阻断。
- 旧票据格式不再读取。

### 阶段 C：工作目录和输入副本

修改内容：

- 新增 `SandboxWorkspaceService` 和 `sandbox_attempts` 表。
- 实现确定性目录、输入清单、复制校验和磁盘空间检查。
- 补重放、冲突、目录逃逸和清理安全测试。

退出条件：

- 相同命令重放不会创建第二个目录。
- 沙箱目录只能位于批准的 project work root。
- rawdata 未修改，输入副本哈希一致。

### 阶段 D：Windows 受限进程

修改内容：

- 实现 `WindowsProcessSandbox` 和 `SandboxProcessRunner`。
- 实现受限制令牌、Job Object、环境变量白名单、超时、取消和完整进程树结束。
- 非 Windows 固定失败，不提供普通进程回退。

退出条件：

- 子进程不能写 rawdata、项目外目录和系统临时目录。
- 超时、取消和父进程退出后没有残留测试辅助进程。
- 敏感环境变量没有传入子进程。

### 阶段 E：输出验证、状态和前端

修改内容：

- 实现 `SandboxOutputVerifier`、原子提升和 Artifact 登记顺序。
- 增加只读 API、Runs 状态面板和 i18n。
- 增加启动中断恢复和终态清理规则。

退出条件：

- 未通过检查的输出不会登记。
- GET 接口无副作用。
- 前端能区分失败、超时、中断和未提供网络隔离。

### 阶段 F：完整验证但仍不开放外部节点

修改内容：

- 运行后端、前端、桌面和 Windows 隔离测试。
- 使用测试辅助程序完成人工流程，不调用真实 MATLAB/SPM/DPABI。
- 更新安全、架构、能力矩阵、开发和桌面文档。
- 再次确认外部节点合同仍为 `executable=false`。

退出条件：

- 全部阻断级测试通过。
- 桌面打包后受限测试辅助进程行为与源码运行一致。
- 没有外部工具能力被误标为 computed 或 validated。

## 16. 证明要求

| 需要证明的结论 | 实施时的验证方法 |
|---|---|
| 没有第二条外部执行路径 | 全仓搜索路由、节点执行函数和 `subprocess` 调用 |

## 17. 明确决策与假设

| 编号 | 决策或假设 | 依据 | 错误时的影响 |
|---|---|---|---|
| A-SBX-01 | 首期只收口应用运行时的外部进程，不迁移原生 Python 科学计算 | 当前原生节点执行函数直接依赖项目存储和科学服务 | 扩大范围会同时重构科学主链和恢复语义 |
| A-SBX-02 | 首期生产执行实现只支持 Windows | 当前桌面发布和外部工具目标主要是 Windows | 其他系统保持失败关闭，不会降低安全性 |
| A-SBX-03 | 使用标准库 `ctypes`，不新增 `pywin32` | 项目已有 `ctypes` 用法，减少打包依赖 | Windows API 封装测试量增加 |
| A-SBX-04 | 外部工具输入全部复制，不使用硬链接 | 硬链接可能让外部程序修改源文件 | 大数据会增加时间和磁盘占用 |
| A-SBX-05 | 失败沙箱默认保留，按保留期清理 | 需要保留错误证据 | 需要磁盘配额和清理检查 |
| A-SBX-06 | 首期不实现网络隔离 | Job Object 和受限制令牌不自动阻断网络 | 必须明确展示未提供，不能宣传完整网络沙箱 |
| A-SBX-07 | 完成本方案不等于开放 MATLAB/SPM/DPABI | 开放能力还需要独立科学和发布验证 | 功能仍保持不可用是预期结果 |

当前没有阻塞方案评审的问题。若用户要求 Linux/macOS 外部执行、容器隔离、网络阻断或将原生 Python 全部迁入子进程，必须另建方案，不能通过本方案中的回退路径实现。

## 19. 完成标准

- 旧 `execute-sandbox` 路由、前端调用和无用服务已删除。
- 应用运行时外部程序只能由 `SandboxProcessRunner` 启动。
- 沙箱策略已绑定 Approval Summary、环境快照、Execution Ticket 和 Gateway。

- 网络隔离明确标为未提供。
- 外部 MATLAB/SPM/DPABI/GPU 节点合同仍保持不可执行。
- 后端、前端、桌面和人工验收全部通过。
- `git diff` 和 `git status --short` 无秘密、研究数据、生成沙箱和无关修改。
