# 阶段五：执行环境快照与票据绑定方案

> 归档状态：该文档对应的当前阶段范围已完成；仅作为历史实施与审计记录保留。

> 状态：已实施并通过最终集成审查
> 依赖：阶段四完成
> 本阶段只绑定执行前已存在的环境事实，不开放新的执行后端。

## 1. 目标

让用户审批的内容不仅包含计划、节点、路径和参数，还包含实际执行环境。审批后如果 MATLAB、SPM、DPABI、Python、GPU 或执行后端发生影响结果的变化，旧审批不能继续分派。

## 2. 当前问题

`ApprovalSummary` 和 `ExecutionTicket` 已绑定计划、证据、记忆、节点、后端、根目录、允许清单和合同版本，但没有环境快照字段。环境探测分散在 `environment_health.py`、`spm_runtime.py` 和具体节点执行器中，审批看到的环境可能与执行时不同。

## 3. 新增 `ExecutionEnvironmentSnapshot`

建议新增 `src/backend/app/schemas/execution_environment.py`：

```python
class ExecutionEnvironmentSnapshot(BaseModel):
    schema_version: Literal[1]
    snapshot_id: str
    project_id: str
    captured_at: datetime
    provider_kind: Literal["local"]
    platform: str
    python_version: str
    app_version: str
    node_registry_hash: str
    contract_versions: tuple[tuple[str, str], ...]
    tool_capabilities: tuple[ToolCapabilitySnapshot, ...]
    backend_capabilities: tuple[BackendCapabilitySnapshot, ...]
    write_roots_hash: str
    readonly_roots_hash: str
    environment_hash: str
```

工具和后端条目至少记录：

- 稳定 ID。
- `available`、`disabled` 或 `unavailable`。
- 版本或可验证的版本摘要。
- 可执行文件或安装根的规范路径哈希。
- 关键配置哈希。
- 探测错误码。

公共接口和审计记录不返回私有绝对路径，只返回稳定 ID、状态、版本、哈希和必要警告。实际路径继续由受控配置服务保管。

## 4. 新增环境服务

新增 `ExecutionEnvironmentService`：

```python
class ExecutionEnvironmentService:
    def capture_for_plan(self, *, project_id: str, reviewed_plan) -> ExecutionEnvironmentSnapshot: ...

    def verify_for_dispatch(
        self,
        *,
        snapshot_id: str,
        expected_hash: str,
        execution_ticket: ExecutionTicket,
    ) -> None: ...
```

`capture_for_plan()` 只探测计划实际使用的节点、后端和外部工具，不扫描无关软件。优先复用现有配置和环境探测服务，不复制 MATLAB/SPM/GPU 检测代码。

`verify_for_dispatch()` 使用同一规范化函数重新计算影响执行的字段。只比较计划相关项，避免无关系统更新使审批失效。

## 5. 审批和票据绑定

### 5.1 审批摘要 `ApprovalSummary`

提升数据结构版本并增加：

- `execution_environment_snapshot_id`
- `execution_environment_hash`
- 环境摘要信息段：列出计划需要的后端、外部工具状态和限制。

环境快照必须在审批摘要构建前持久化，`summary_hash` 必须覆盖环境哈希。

### 5.2 执行票据 `ExecutionTicket`

提升数据结构版本并增加：

- `execution_environment_snapshot_id`
- `execution_environment_hash`
- `execution_provider_kind`

执行票据的 `canonical_hash` 必须覆盖这些字段。恢复子票据继承父票据的环境约束；如恢复需要不同后端或工具，必须生成新的恢复审批，不能静默切换。

### 5.3 执行网关

在分派前增加以下顺序：

```text
校验执行票据未过期且未消费
-> 校验计划、审批、范围和允许清单哈希
-> verify_for_dispatch()
-> 试执行已通过
-> 消费执行票据
-> 分派
```

环境不一致时返回 `EXECUTION_ENVIRONMENT_CHANGED`，执行票据不消费，运行记录不创建，节点执行器不调用。系统回到需要重新生成审批摘要的状态，由用户重新审批。

## 6. 本地执行世界一致性

当前只支持 `provider_kind="local"`。同一次执行中：

- 文件探测、路径校验和子进程执行必须使用同一项目配置与本地环境快照。
- 不允许文件检查在主机、命令执行在容器，或反过来。
- 未来若增加容器或远程执行，必须作为独立任务同时实现文件、进程、路径、审计和产物注册，不在本阶段预留半成品切换字段。

## 7. 持久化和展示

- 快照使用 SQLite 或现有权威存储的不可变记录，不写到 `rawdata`。
- 快照只保存受控元数据和 hash，不复制环境变量全集。
- 任务详情和审批界面显示简短环境摘要：后端、外部工具是否可用、版本和警告。
- 普通页面不显示本机路径。
- `Trace` 记录快照 ID 和哈希，`Replay` 只读取，不重新探测环境。

## 8. 风险和处理

| 编号 | 风险 | 处理 | 证明方式 |
|---|---|---|---|
| H-07 | 环境变化后仍使用旧审批 | 审批摘要和执行票据同时绑定环境哈希，执行网关再校验 | 修改版本、路径或后端后分派被拒绝 |
| H-07A | 无关软件变化使所有审批失效 | 快照只包含计划实际使用项 | 修改无关工具不改变哈希 |
| H-07B | 快照泄露私有路径或环境变量 | 对外只保存路径 hash 和白名单字段 | API/序列化安全测试 |
| H-07C | 探测与节点执行器使用不同配置 | 两者注入同一 `ConfigService` 和执行方式 | 依赖一致性测试 |
| H-07D | 恢复任务静默改后端 | 子票据继承环境约束，变更需新审批 | 恢复合同测试 |

## 9. 测试

必须覆盖：

1. 相同环境生成相同规范哈希；时间和快照 ID 不影响哈希。
2. 计划使用的工具版本、路径、后端、节点注册表或合同版本变化会改变哈希。
3. 无关工具变化不改变当前计划的环境哈希。
4. 审批摘要哈希和执行票据规范哈希覆盖环境哈希。
5. 环境变化时执行网关不消费票据、不创建运行记录、不调用节点执行器。
6. 环境一致时原有审批顺序和分派继续通过。
7. 恢复子票据不可切换未批准后端。
8. 接口、`Trace` 和日志不包含私有绝对路径、凭据或环境变量全集。

- 审批摘要、执行票据和执行网关使用同一环境哈希。

- 环境一致性和安全序列化测试通过。
- 原有审批门、试执行、执行票据、执行网关顺序保持不变。
