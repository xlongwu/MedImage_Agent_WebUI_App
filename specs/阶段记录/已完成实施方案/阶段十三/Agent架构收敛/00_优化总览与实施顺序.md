# Agent 架构收敛优化总览

> 归档状态：该文档对应的当前阶段范围已完成；仅作为历史实施与审计记录保留。

> 状态：已实施并通过最终集成审查
> 任务模式：架构调整
> 适用范围：当前 `MedImage_Agent` 源码
> 依据：对话记录 `01a0046a-a32d-7811-8281-2aa7fb50c949`、当前源码、`docs/架构与决策/系统架构.md`、`docs/规划与运行时/受控单AgentHarness.md`、阶段十二 Agent 改造文档，以及 `deepseek-harness` 的持久记录、检查点和运行时自检设计。

## 1. 本轮目标

本轮只解决当前 Agent 中仍然存在的结构问题，不重做已经完成的审批、执行、结果验证和回放能力。

最终应达到以下结果：

1. 规划只走 Agent 任务主链，删除旧的 `/api/agent/plan` 和文件型 Agent 运行记录旁路。
2. 模型只返回 `request_decision` 或 `draft_plan`，每种动作都有固定字段。
3. 每次模型请求的哈希都由真实请求内容生成，能够证明“当时到底发了什么”。
4. 模型只看到当前步骤需要的信息；必要证据不能因为长度限制被静默丢弃。
5. 任务创建、模型调用、动作落库和后台唤醒都有明确的持久化边界，服务重启后可以继续。
6. 审批时绑定执行环境快照；审批后环境变化时阻止执行并要求重新确认。
7. 增加只读运行时自检，尽早发现状态、调用记录和执行票据之间的不一致。
8. 本轮不实现生产多 Agent；只保留进入下一阶段前必须满足的条件。
9. 增加只读流程图：计划生成后显示真实有向无环图，执行后覆盖权威节点状态。
10. 收口旧 sandbox 入口，并建立只能由执行网关调用的受限进程沙箱。
11. 修正 Skill 和文档差异，增加真实 Agent 评估、Memory/Context 质量检查和项目级运行指标。

## 2. 范围和非目标

### 2.1 本轮修改范围

- Agent 任务规划入口、模型动作、模型请求记录和上下文构建。
- `AgentTaskCommandService` 与 `AgentHarnessService` 的职责拆分。
- Agent 后台唤醒、模型调用和动作应用的持久化检查点。
- 审批摘要、执行票据与执行环境快照的绑定。
- Agent 状态、调用记录和执行票据的只读一致性检查。
- Reviewed Plan 有向无环图、运行节点状态投影和前端流程图。
- 沙箱策略、独立工作目录、Windows 受限进程、输出验证和运行状态展示。
- 模型配置身份、Agent Eval Runner、Memory/Context 质量案例和项目级运行汇总。
- 对应后端、前端、命令行、测试和文档。

### 2.2 本轮不做

- 不改变审批门、执行网关、流水线运行时和节点执行器的唯一执行边界。
- 不开放外部命令、MATLAB、SPM、DPABI、GPU 或 DICOM 的默认执行能力。
- 不修改科学算法，不提高任何能力等级。
- 不把受控循环默认开关改为开启。
- 不做兼容层，不同时保留新旧规划入口。
- 不实现生产多 Agent、递归委派、Agent 自建工具或 Agent 自改代码。
- 不做发布、安装包或版本号变更。
- 不因沙箱基础设施完成而开放 MATLAB、SPM、DPABI、GPU 或任意外部命令。

## 3. 当前问题和处理阶段

### 3.1 从对话和 `deepseek-harness` 采用的做法

| 可采用做法 | 在本项目中的落点 |
|---|---|
| 模型调用和副作用之前先落库 | 阶段二的调用开始记录；阶段四的事务检查点 |
| 模型能看到的信息必须可追溯 | 阶段二记录真实请求哈希；阶段三记录上下文引用和遗漏项 |
| 长期记录与模型可见内容分开 | 数据库保留完整结构化状态，模型只接收当前动作需要的投影 |
| 共享服务由启动入口统一组装 | 阶段四移除服务构造函数中的隐式配置和存储创建 |
| 用明确规则检查跨记录一致性 | 阶段六增加只读运行时自检 |
| 多 Agent 必须可限制、可关闭 | 阶段七只做离线只读评审，并设置进入生产的门槛 |

### 3.2 明确不照搬的做法

- 不把所有模块都改成插件；当前只有模型服务、存储和执行后端需要清楚替换边界。
- 不引入通用聊天记录压缩和磁盘溢写；本项目使用结构化任务、证据和产物引用。
- 不引入可逆外部工具调用框架；实际执行继续服从审批门、执行票据和执行网关。
- 不引入无限循环或递归多 Agent；单次唤醒继续受步骤、预算和时间限制。

## 4. 实施顺序

```text
阶段一：收敛规划主链
  -> 阶段二：收紧模型动作和请求记录
  -> 阶段三：按动作构建上下文
  -> 阶段四：拆分服务并补持久化检查点
  -> 阶段五：绑定执行环境快照
  -> 阶段六：增加运行时自检并做完整回归
  -> 阶段七：重新判断是否需要生产多 Agent
  -> 收尾质量修复：真实评估、运行指标和沙箱验收
```

不得跳过前一阶段直接实施后一阶段。每阶段单独评审、单独合并；共享文件同一时间只能有一个实现所有者。

| 独立安全改造 | `09_统一沙箱执行改造方案.md` | 旧入口删除、策略绑定、受限进程、输出验证和状态展示 | 外部进程只有一个受控出口，且外部能力仍保持关闭 |
| 收尾质量修复 | `10_Agent必备环节完整优化修复方案.md` | Skill 真实状态、模型配置身份、真实 Agent Eval、运行指标和沙箱验收 | 固定案例可自动运行并阻止质量退化，异常状态可见 |

流程图功能不依赖阶段二至七，可在阶段一完成后独立排期。它会修改受保护的 Pipeline Runtime，因此必须单独执行运行时特征测试和完整回归，不与其他运行时修改并行实施。

沙箱改造依赖阶段五的环境快照和票据绑定，应在阶段五完成后单独实施。它会修改 Execution Ticket、Execution Gateway、Pipeline Runtime 和桌面打包，不得与阶段五、阶段六或其他运行时改造并行实施。完成沙箱基础设施不代表允许外部工具执行；开放任何外部节点必须另立任务。

收尾质量修复依赖当前 Planning、Context、State、Memory、Runtime、Guardrails、流程图和沙箱基础设施。先完成 Skill 与文档修正，再实施模型配置绑定和真实 Agent Eval；运行指标在评估结果可信后接入，Windows 沙箱打包验收最后单独执行。

## 6. 统一实施规则

每个阶段都必须按以下顺序执行：

1. 运行 `git status --short`，记录并保留用户已有改动。
2. 为当前行为补充或确认回归测试。
3. 修改数据结构和存储，再修改服务、路由、前端和文档。
4. 删除旧实现前执行全仓引用搜索。
5. 运行阶段文档中的针对性测试。
6. 对照本文件和阶段文件逐项复核；不满足退出条件时不得进入下一阶段。
7. 检查 `git diff`、`git status --short`，确认没有研究数据、凭据、生成物和无关修改。

所有持久格式变更采用一次性切换：同步更新当前消费者并删除旧字段和旧读取逻辑，不增加回退或迁移读取。

## 7. 总体验收

- 从用户目标到 Reviewed Plan 只有一条主链。
- 模型不能直接执行、审批、创建执行票据或修改科学结果等级。
- 模型请求、响应和动作都有不含原文的稳定哈希与状态记录。
- 必要上下文缺失会返回结构化错误，不会生成看似完整的计划。
- 服务重启、重复命令、重复唤醒和并发工作进程不产生重复副作用。
- 审批后环境改变会使旧审批摘要或执行票据失效。
- 运行时自检只报告和阻断，不自动修数据库或扩大权限。
- rawdata 和登记源数据保持只读。
- 外部进程只有统一沙箱出口，失败时不回退为普通进程。
- 固定 Agent 案例由真实命令链运行，安全指标退化会使 CI 失败。
- 项目级运行汇总只能读取权威记录，不产生规划、恢复或执行副作用。
- 阶段七评估前，生产运行仍固定为 `single_agent`。
