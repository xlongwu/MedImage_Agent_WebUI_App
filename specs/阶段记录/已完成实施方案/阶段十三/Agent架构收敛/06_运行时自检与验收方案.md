# 阶段六：运行时自检与验收方案

> 归档状态：该文档对应的当前阶段范围已完成；仅作为历史实施与审计记录保留。

> 状态：已实施并通过最终集成审查
> 依赖：阶段五完成
> 本阶段增加只读检查和完整回归，不自动修复生产状态。

## 1. 目标

把当前依赖人工 `Trace` 和 `Replay` 才能发现的问题变成明确、可测试的检查规则。发现阻断级错误时停止继续推进，并保留足够证据供人工处理。

## 2. 自检器边界

新增 `AgentInvariantChecker`。它只能：

- 读取任务生命周期、命令、决定、计划、摘要、调用、动作、执行票据、运行、产物和事务发件箱记录。
- 返回结构化检查结果。
- 对阻断级结果要求调用方停止推进。
- 写一条不含研究数据的审计事件。

它不能：

- 修改状态或补写缺失记录。
- 自动审批、重建执行票据、重跑模型或分派。
- 扫描 `rawdata` 内容。
- 把历史审批当成当前权限。

## 3. 检查结果结构

```python
class AgentInvariantFinding(BaseModel):
    code: str
    severity: Literal["warning", "blocking"]
    lifecycle_id: str
    related_ids: tuple[str, ...]
    message_key: str
    evidence_hashes: tuple[str, ...]
```

公共接口使用 `code` 和 `message_key`，前端通过多语言目录显示。不得把内部异常堆栈作为用户文案。

## 4. 第一批必须实现的规则

| 检查码 | 条件 | 级别 | 处理 |
|---|---|---|---|
| `AGENT_INV_MULTIPLE_PENDING_DECISIONS` | 同一任务有多个未解决决定批次 | 阻断 | 停止规划，人工检查 |
| `AGENT_INV_PLAN_WITHOUT_INPUT_HASH` | 审阅计划缺目标、科学回答或证据绑定 | 阻断 | 禁止生成审批摘要 |
| `AGENT_INV_SUMMARY_PLAN_MISMATCH` | 审批摘要的计划哈希与当前计划不同 | 阻断 | 禁止审批和执行 |
| `AGENT_INV_CALL_WITHOUT_REQUEST_HASH` | 模型服务已调用但没有真实请求哈希 | 阻断 | 停止受控循环 |
| `AGENT_INV_ACTION_WITHOUT_CALL` | 动作找不到对应已完成调用 | 阻断 | 不应用动作 |
| `AGENT_INV_APPLIED_ACTION_STATE_MISMATCH` | 动作标记已完成，但任务状态没有对应结果 | 阻断 | 停止自动推进 |
| `AGENT_INV_WAKE_MISSING` | 状态可继续但没有唤醒、发件箱或有效租约 | 警告 | 调度器重新登记一次唤醒 |
| `AGENT_INV_DUPLICATE_ACTIVE_LEASE` | 同一步存在多个有效所有者 | 阻断 | 不允许第二个工作进程推进 |
| `AGENT_INV_TICKET_SUMMARY_MISMATCH` | 执行票据与审批摘要、环境或范围哈希不一致 | 阻断 | 执行网关拒绝 |
| `AGENT_INV_TICKET_WITHOUT_APPROVAL` | 执行票据找不到有效审批 | 阻断 | 执行网关拒绝 |
| `AGENT_INV_RUN_WITHOUT_CONSUMED_TICKET` | 运行记录已创建但执行票据未消费 | 阻断 | 标记需人工调查，不自动删除运行记录 |
| `AGENT_INV_COMPLETED_WITHOUT_ARTIFACT_TRUTH` | 状态声称已计算或已完成，但产物不可重载 | 阻断 | 结果投影不得显示成功 |
| `AGENT_INV_PLAN_ONLY_HAS_EXECUTION` | 仅规划任务出现执行票据、运行记录或数值产物 | 阻断 | 停止并审计 |

只有 `AGENT_INV_WAKE_MISSING` 允许调用方按既有规则补登记唤醒；这不是修改业务状态。其他检查结果不自动修复。

## 5. 调用位置

### 5.1 写入后检查

在开发和测试环境中，对以下操作完成后检查当前任务生命周期：

- 创建或回答提交。
- 模型调用和动作应用完成。
- 审阅计划和审批摘要持久化。
- 审批、执行票据签发和分派。
- 运行终态和结果投影。

生产环境不在每个 GET 请求上运行检查，避免读接口产生副作用或性能不稳定。

### 5.2 启动检查

应用启动时只扫描：

- 非终态任务。
- 未消费唤醒或发件箱。
- 未完成调用或动作。
- 已签发执行票据。
- 最近有变化的运行记录。

扫描必须有数量和时间上限。超限时记录结构化警告，并由运维命令继续只读扫描；不得阻塞整个应用启动。

### 5.3 人工诊断入口

提供内部诊断服务或受保护接口，支持按 `lifecycle_id` 检查。默认只返回检查结果、关联 ID 和哈希，不返回上下文正文、路径或数据。

## 6. 与 `Trace`、`Replay` 的关系

- `AgentInvariantChecker` 回答“当前记录是否互相一致”。
- `Trace` 回答“发生过哪些步骤”。
- `Replay` 回答“用已记录输入能否重现确定性判断”。

三者共用相同 ID 和哈希，但不得互相调用形成循环。`Replay` 仍然禁止调用模型服务、执行或修改状态。

## 8. 故障注入场景

至少覆盖以下中断点：

1. 任务生命周期写入后、唤醒入队前。
2. 模型调用开始记录写入后、网络调用前。
3. 模型服务返回后、响应哈希写入前。
4. 动作已接受记录写入后、业务状态写入前。
5. 审阅计划写入后、审批摘要写入前。
6. 审批记录写入后、试执行前。
7. 执行票据签发后、执行网关分派前。
8. 执行网关消费票据后、运行记录写入前。
9. 运行完成后、产物注册或结果投影前。

每个场景必须说明：重启后由谁读取哪条记录、是否允许重试、如何避免重复副作用、最终用户看到什么状态。

## 10. 风险和处理

| 编号 | 风险 | 处理 | 证明方式 |
|---|---|---|---|
| H-08 | 自检器变成自动修复器 | 接口只返回检查结果；仅缺唤醒可重新登记 | 存储写入调用检查 |
| H-08A | GET 请求触发扫描或状态变化 | 自检只在命令、启动和显式诊断调用 | GET 纯读测试 |
| H-08B | 启动扫描过大 | 只扫活跃记录并设置上限 | 大量历史记录启动测试 |
| H-08C | 检查结果泄露路径或数据 | 只返回错误码、ID 和哈希 | 接口安全序列化测试 |
| H-08D | 规则误报导致正常任务阻断 | 每条规则都有正例和近似反例 | 参数化规则测试 |
