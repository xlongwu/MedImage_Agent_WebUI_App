```python
app.add_middleware(CORSMiddleware, ...)        # 第 1 个注册
```

## Phase 6A — 仓库规则与 CI 稳定化

### 目标

消除当前规则冲突，让以后每次开发都有可靠的自动验证基础。

### 具体任务

#### 6A-1: 修复 ERROR_KB.yaml 规则冲突

**当前问题：**
`.gitignore` 中 `memory/` 屏蔽了全部 memory 目录，但 `memory/global/ERROR_KB.yaml` 是运行时依赖，被 4 个源文件引用。之前清理时误删导致过 7 个测试失败。

**决策：采用优先方案 — 迁移到 `src/backend/app/resources/`**

理由：
1. 将运行时静态资源放在源码目录下是标准工程实践
2. 避免 `.gitignore` 规则的特殊例外
3. 让 `error_classifier` 从明确的资源目录加载，路径更短、更可靠

**具体变更：**
- 将 `memory/global/ERROR_KB.yaml` 迁移到 `src/backend/app/resources/error_kb.yaml`
- 更新 `error_classifier.py` 的 `_DEFAULT_KB_REL` 为新路径
- 更新 `memory_store.py` 的加载路径
- 更新 `file_provider.py` 的相关逻辑

## Phase 6C — 真实预处理完整链路

### 目标

基于 Phase 6B 产生的 converted BIDS/NIfTI，跑通当前已实现的预处理链：

Registration → Create preprocessing run → Python preflight → Slice Timing + Realign → Coregistration + Normalization → Smoothing → Nuisance Regression → Temporal Filtering → ALFF/fALFF → ReHo → FC → Validation → Report

### 交付要求

每个 stage 必须是一个完整状态单元：

```
状态: not_started | planned | dry_run_ready | running | succeeded | failed | metadata_only | blocked
```

每个 stage 必须记录：input manifest、parameters、output manifest、provenance、stdout/stderr、checksum、duration、next-stage readiness。

### 必须解决的问题

#### 6C-1: 中断恢复

应用或 backend 重启后：
- 已成功 stage 不重复执行
- 失败 stage 可以重试
- 当前 run 可以恢复
- 不丢失 stage registry

#### 6C-2: 输入输出一致性

每一阶段**只读取上一阶段注册的输出**，不能重新猜测文件路径。

```
Slice Timing + Realign → registration outputs
  → Coreg/Norm → input manifest ← 上一阶段注册输出
    → Coreg/Norm → registration outputs
      → Smoothing → input manifest ← 上一阶段注册输出
```

#### 6C-3: 失败处理

单 subject 失败时允许：stop all / continue remaining subjects / retry failed subjects。

#### 6C-4: GUI 状态

Preprocessing workspace 应展示：overall progress、subject-level progress、stage-level progress、blockers、logs、artifacts、validation、report export。

### 完成标准

- [ ] 3 个 subject 均能完成已支持阶段，或失败原因明确
- [ ] 所有 stage 产物都在 sandbox/workspace
- [ ] rawdata 和 converted input 不被覆盖
- [ ] pipeline validation 能正确反映真实状态
- [ ] report 中的数字来自实际执行结果，不是 placeholder
- [ ] 本地 EXE 流程可以从转换后一直操作到报告

## Phase 6D — 科研算法标准化与 RC 冻结

### 目标

将"流程能运行"提升为"结果具备科研可信度"。

### 优先算法

#### 6D-1: Nuisance Regression 标准化

- motion 6/12/24 参数
- WM/CSF/global signal 可选
- polynomial trends
- censoring/scrubbing
- design matrix rank 检查
- residual DOF
- 共线性警告

#### 6D-2: Temporal Filtering 标准化

- TR 自动读取
- Nyquist 校验
- Butterworth 或 FFT filter
- 边界效应策略
- filtering 与 regression 顺序明确
- 与参考实现数值对比

#### 6D-3: ALFF/fALFF 标准化

FFT → amplitude spectrum → target frequency band → ALFF → whole spectrum denominator → fALFF → optional z-standardization

当前代码分析：`alff_compute.py` 已有 FFT-based 实现，包括 `compute_alff_numpy()` 和 `compute_alff_cupy()`。需增强 z-standardization 选项。

#### 6D-4: ReHo 标准化

Kendall's coefficient of concordance (KCC)：7/19/27 neighbors、mask、edge handling、tie correction、optional normalization。

当前代码分析：`reho_compute.py` 已实现 KCC 和 tie correction。需验证与 DPABI/SPM 的一致性和添加 normalization 选项。

#### 6D-5: FC 标准化

Atlas parcellation → ROI time series extraction → confound-aware valid timepoints → Pearson/Spearman → Fisher-z → ROI × ROI matrix。

当前代码分析：`functional_connectivity_compute.py` 已有 ROI-based correlation 和 Fisher-z。需增加 Spearman 选项和 confound-aware 处理。

### Golden Dataset 验证

为每个算法准备小型固定数据集，与至少一个参考实现比较：

| 参考 | 方法 |
|---|---|
| DPABI | MATLAB 执行 |
| SPM | MATLAB 执行 |
| Nilearn | Python 执行 |
| 自建 NumPy reference | 纯 Python baseline |

**定义容差：**
- max absolute error
- mean absolute error
- correlation
- Dice/mask agreement
