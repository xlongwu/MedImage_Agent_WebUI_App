## 范围与历史

原范围为输入/审批等待不消耗活跃预算、长运行由独立协调 owner 追踪、规划与执行恢复分离、停机后恢复持久 checkpoint。历史主体提交 `767ed7b7`，收尾提交 `e677293f`；它们是实现来源，不是本次候选的验收结论。原阶段 3.B 的前 100 项目截断与无界执行扫描由本次 R-02 修复。H05 指 OBSERVING/EVALUATING 的中间恢复，不能用它代替 F02 尾部覆盖或 D-10 资源边界。

## 当前实现与对应证据

- `SQLiteDesktopStore.scan_agent_recovery_page` 按 eligible lifecycle 直接筛选，每页最多 100，稳定 ID keyset 与固定周期上界；checkpoint version 1。缺失 wake 登记与 cursor 同事务，崩溃不会跳过未提交页；新增低 ID 在下一周期进入。
- 自动扫描只选择当前 lifecycle schema；旧版本原载荷保留、不会自动恢复或迁移，显式读取仍返回版本拒绝。旧版本等待任务不能阻断当前版本尾部恢复。
- `AgentTaskScheduler` 只推进规划；`AgentExecutionCoordinator` 只协调原 run 和已保存中间 checkpoint。有限周期由现有 worker 续扫，不依赖新用户命令；已消费 wake 不复活，不创建新的 ticket/run/dispatch。
- lease、fair yield、等待时间扣除、结果未知不重发沿用既有确定性合同。跨批用户回答由真实生命周期事件桥接 Replay，不能仅比较相邻模型步骤状态。
