## 本次缺口与修复

R-09 新正式失败回归证明：科学建议被 `continue` 跳过来源引用；首个 Harness 请求尚未构建 MemoryContext；缓存会绕过当前 consent/forget；静态 Product Skill 的 section 白名单没有 memory_context，实际 provider 请求会丢掉它。现在建议及来源均进入规范化 hash；每次规划/provider 消费前重读当前检索、项目范围和实际 context hash，刷新权威 lifecycle 与证据。Product Skill 的允许输入同步，manifest identity 由实际规范化 manifest/Markdown 导出，动作仍仅 request_decision/draft_plan。

`tests/integration/test_agent_offline_consumers.py` 使用真实 `MemoryManagementService`、独立 repository、consolidation/retrieval、Harness 和捕获 CanonicalModelRequest 的 scripted adapter。参数化后共七例，检查实际提交内容、revision/hash/引用、冲突建议不定值、跨项目无建议、forget 后旧缓存消失、明文清除/tombstone、consent 关闭、损坏/外项目 context 在 provider 前拒绝，以及跨批 reopen。没有网络请求，没有将假计算计成成功。

冲突 guard 必须检查同一参数的所有建议，不能由字典最后一项覆盖前项。真实 batch 同时选择互斥建议时返回字段级拒绝，权威 lifecycle 不改变。保存方案测试绑定实际检索 hash/refs；该测试显式调用 ApprovalSummary 构造器只验证身份合同，不代表 plan-only 工作流创建执行审批。生产 plan-only 保存器已由禁止调用审批构造器的回归证明不创建摘要/envelope、ticket 或 run。

R-05 当前任务确认绑定 goal/kind/value/证据/batch/过期状态；重复模型问题与 command replay 分开处理。混合批次仅跳过仍有效的确认，过期答案重新提问。记忆建议本身不成为确认、执行权限或环境事实。
