## 调用链与修改边界

- 提问：`AgentPlanningService` → `AgentHarnessService` → `AgentPlanningActionService` →
  `AgentOrchestrator.transition` → `SQLiteDesktopStore.transition_agent_lifecycle`。
  lifecycle 和 event 当前同事务；action accepted/applied 单独写入，阶段 1 需绑定业务结果 ID/hash。
- 调度：命令事务 wake → `AgentTaskScheduler` → `advance_planning`。wake claim、retry、complete 在存储侧；
  attempt 的 status/step/context/lease fence 不能被新的 worker 逻辑绕过。
- 调用：canonical request → started step/model call → provider → completed call → attempt 结算。
  恢复 `_is_pre_network_call` 当前依赖 network_called，阶段 2 必须测试真实写入顺序。
- 执行观察：`AgentTaskReconciler` → `AgentOrchestrator.observe/evaluate_goal/propose_recovery`。
  阶段 3 不增加科学 dispatch 路径，GET 继续只读。
- 记忆：独立 `MemoryRepository` → `MemoryRetrievalService` → `MemoryContext` → Harness/科学确认。
  禁止将记忆作为权限或当前环境事实。
- 展示：后端 Agent Task schema/read model → 前端 `lib/types/agentTask.ts`、API wrapper、Agent feature 和 i18n。
  阶段 1–5 修改公开字段时必须同步 Trace、Replay、不变量检查和前端消费者。
