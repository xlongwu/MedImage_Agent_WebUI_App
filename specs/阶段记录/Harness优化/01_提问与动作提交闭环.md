# Harness 优化：阶段 1 提问与动作提交闭环

## 范围与结论

任务模式：Feature Bundle。本阶段将阶段 0 的 H01、H02 从缺陷行为刻画替换为正确合同，
覆盖 Harness 的模型 action 到 Agent Task 回答及继续规划链路；不增加执行、审批、Gateway、
runner 或文件系统能力。

## 问题、修改与回归

| 问题 | 修复行为 | 回归证据 |
|---|---|---|
| H01：首次 Harness 问题使用占位 evidence hash | accepted action 记录本次持久化 Context 的 hash、Evidence snapshot hash 和 purpose；decision batch 使用这些真实来源。回答用相同 purpose 重建证据，未改变时继续规划，改变时仍拒绝。 | `test_first_question_answer_uses_the_persisted_evidence_snapshot`；Harness service action-record assertions。 |
| H02：Action 状态冲突触发 `AttributeError` | 统一抛出 `AGENT_HARNESS_ACTION_STATE_CONFLICT`。 | `test_action_conflict_returns_the_structured_domain_error`。 |
| 动作与业务结果断链 | `request_decision` 在单个 SQLite 事务中写入 lifecycle、event、pending batch 和 `AgentActionRecord(applied)`；action 保存 decision batch ID/hash。`draft_plan` 保存 Reviewed Plan ID/hash，或其后续 decision batch ID/hash。 | Harness action acceptance/applied 回归与 lifecycle 集成套件。 |

已接受 action 在崩溃恢复时继续只使用持久化 action；不会重新调用 provider。`draft_plan`
仍走既有确定性 Planning Service，保持其现有 validator、Reviewed Plan 和 Approval Summary
边界。本阶段未改变其执行权限。

## 验收场景

- 成功：首次 `request_decision` 后提交同一批答案，状态从等待科学决定进入 `PLAN_DRAFTED`。
- 失败：缺失 lifecycle 的 Action 返回结构化冲突；原有 evidence 变化检查仍拒绝旧回答。
- 重启：已有 accepted action 的恢复测试确认不会重放 provider；已完成 decision 的 action
  可由其已保存的 batch ID/hash 关联。
