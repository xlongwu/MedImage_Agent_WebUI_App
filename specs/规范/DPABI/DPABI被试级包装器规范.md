This document defines the MVP subject-level DPABI single-function wrapper.

## Goals

The subject wrapper safely applies selected DPABI utility functions to synthetic subject-level data.

The MVP focuses on:

- y_Smooth
- rest_Smooth
- synthetic BIDS-like input only
- subject-level execution
- derivative output
- engineering comparison with SPM smoothing if available
- audit-friendly result JSON
- dataset-level summary report

## Scope

Supported in this step:

- read synthetic dataset_index.json
- run allowlisted DPABI smoothing function per subject
- write derivatives under derivatives/dpabi_single_function
- write subject result JSON
- aggregate dataset-level summary
- optional comparison with SPM smoothing outputs
- API and frontend visibility

Unsupported in this step:

- full DPABI preprocessing
- DPARSF_run execution
- DPARSFA_run execution
- DPABI GUI automation
- real medical image preprocessing
- rawdata modification
- DPABI source modification
- deletion of files
- clinical interpretation

## Inputs

```text
work/dataset_index/dataset_index.json
work/dpabi/dpabi_wrapper_contracts.json
examples/project_config_dataset.yaml
```

## Outputs

```text
derivatives/dpabi_single_function/{subject_id}/func/{subject_id}_dpabi_smooth.nii
derivatives/dpabi_single_function/{subject_id}/func/dpabi_subject_wrapper_result.json
reports/dpabi/dpabi_subject_wrapper_summary.json
reports/dpabi/dpabi_subject_wrapper_report.md
```

## Allowlisted Functions

- y_Smooth
- rest_Smooth

## Safety Rules

- Do not run DPARSF_run.
- Do not run DPARSFA_run.
- Do not call DPABI GUI.
- Do not modify rawdata.
- Do not modify DPABI source.
- Do not delete files.
- Only process synthetic BIDS-like data generated by this project.
- Treat outputs as engineering integration artifacts only.
