# Apple 风格前端设计系统

本文记录 MedImage Agent 当前前端壳层、视觉令牌和核心工作区的长期实现约束。它不改变
后端执行、审批、科学能力或数据安全边界；当前行为仍以源码和测试为准。

## 设计原则

- 使用克制、清晰、低装饰的 Apple 风格视觉语言，优先保证科研工作流的层级与可读性。
- 依靠间距、字体层级、浅色材质和细分隔线组织信息，避免用高饱和色或大面积阴影制造层级。
- 颜色只表达选择、状态和警示；机器 ID、hash、错误码及科学证据保持原始语义。
- 不用占位图、虚构指标或本地乐观状态模拟计算、审批、验证和产物成功。
- 所有写入、执行和审批仍由后端 Approval Gate、Execution Ticket 和权威状态控制。

## 应用壳层

`AppShell` 使用五个明确插槽：

```text
Global Navigation Rail | Context Sidebar | Main Workspace | Inspector
                                      Status Bar
```

- Global Navigation Rail 固定承担 Projects、Overview、Plan、Preprocessing、QC、Results、
  Runs 和 Settings 的一级导航。
- Context Sidebar 只在需要项目切换或局部导航时出现，不复制全局导航。
- Main Workspace 承载当前任务；页面操作必须属于当前工作流上下文。
- Inspector 只呈现后端来源的上下文、证据和助手内容，不提供绕过审批的执行开关。
- Status Bar 展示任务和运行摘要，不遮挡主工作区。

`workspaceChromePresetForLocation()` 是路由到壳层预设的单一映射入口。新增工作区时应先
选择最窄的现有预设，确有新的布局职责时再扩展预设。

## 视觉令牌

核心尺寸和材质由 `src/frontend/src/styles/tokens.css` 统一维护：

- 顶栏 `52px`；
- 全局导航栏 `56px`；
- 上下文侧栏 `280px`；
- 检查器 `336px`；
- 状态栏 `40px`；
- `material-sidebar`、`material-toolbar`、`selection-strong` 同时提供浅色和深色语义。

组件必须优先使用语义令牌。禁止在业务页面复制一套新的品牌色、圆角、阴影或深色模式
规则。数据表、表单和交互目标必须保留键盘焦点及可访问名称。

## 核心页面

### Projects

项目库使用可搜索、可筛选、可排序的行式列表。列信息只来自真实项目字段，缺少值时显示
明确的不可用状态。选中与悬停操作不改变后端项目事实。

### Project Overview

总览包含项目抬头、真实工作流进度、数据/模型/最近运行卡片、下一步建议和计划节点图。
计划节点图只表示 Reviewed Plan 中存在的节点，不推断单节点已执行或已验证。

### Image Workspace

医学影像查看器采用控制区、画布区和 QC/证据区三列结构。只有真实 `preview_url` 才渲染
医学图像；高级叠加和指标在缺少已登记证据时明确禁用。亮度、对比度、切片和键盘导航只
作用于当前预览，不写入源数据。

### Runs / Task Workspace

任务工作区采用任务列表、权威审批/运行详情、产物检查器三列结构，并保留 History 视图。
审批区只展示后端 Agent Task 的摘要、hash、状态和 rawdata 保护信息；实际审批必须进入
受控 Agent 工作区。运行详情和产物来自项目 run API，不生成客户端成功状态。

### Assistant

入口文案是"解释当前任务"，不是通用助手：Goal Composer 仍是唯一的任务创建入口。宽屏总览
可将它停靠在检查器列；窄屏使用 Sheet。两种形式共享同一内容组件，提示建议只能填充输入，
不得自动执行、批准、导出或修改配置；没有选中项目时只呈现只读边界，不呈现提示建议。
Agent 任务卡的"解释此任务"按钮也只预填当前任务上下文并打开该入口，不提交任何命令。

## 工作区栅格与卡片节奏

- 桌面端同一视觉行内的卡片必须使用 `align-items: stretch`，卡片根节点使用
  `height: 100%` 和 `box-sizing: border-box`，避免内容较少的卡片悬在同排长卡片上方。
- 两列共享面板使用 `WorkspaceLayout.module.css` 的 `panelGrid`。同一行的直接子项会等高；
  只有一个直接子项时必须占满整行，不得保留空白的第二列。
- 内容量明显不同的模块应通过明确的 `grid-template-areas`、列跨度或顺序形成完整行。例如
  Plan 固定为“方案摘要 / 流程图 / 检查器”，QC 在宽屏使用 7:5 概览行和三等分分析行。
- 大型表格、影像查看器和技术控制台可以有意占满整行；小型摘要卡不得单独落在半宽尾行。
- 等高规则只改变视觉排布，不得裁切权威错误、审批、证据、产物或科学参数。内容增长时页面
  应自然增高；不得用固定像素高度、隐藏溢出或截断业务模块来制造表面一致。

## 响应式规则

- `>= 1440px`：允许上下文侧栏和停靠检查器同时存在。
- `1180px - 1439px`：保留全局导航栏，隐藏上下文侧栏，检查器按需覆盖。
- `< 1180px`：复杂三列工作区逐步折叠为双列或单列，主任务始终优先。
- `1024px` 是桌面最小验收宽度；`1280px`、`1440px` 和 `1920px` 是必检宽度。

响应式变化只能改变布局，不得隐藏权威错误、审批状态、数据来源或 rawdata 保护信息。

## 变更与验收

前端视觉变更至少运行 format、typecheck、Vitest 和 production build。壳层、查看器或核心
工作区变化还应按《前端视觉验收基线》检查 `1024`、`1280`、`1440` 和 `1920` 宽度，并
覆盖空状态、失败状态、深色模式、键盘路径以及检查器开闭状态。未执行的人工或 Electron
验证必须在交付报告中明确说明。
