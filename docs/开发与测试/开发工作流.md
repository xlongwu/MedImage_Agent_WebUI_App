# Agent 开发工作流

本文档是 `AGENTS.md` 的开发流程伴随文档，提供当前仓库可执行的日常命令和交付顺序。安全、科学、兼容、文档同步与完成标准以根目录 `AGENTS.md` 为准；本文件不重复其全部规则。

## 1. 开发入口

开始任务前必须：

1. 阅读 `AGENTS.md`、任务说明和直接相关的专项文档；
2. 使用 `git status --short` 识别并保留用户已有修改；工作区不必干净，但不得覆盖无关变更；
3. 选择 Focused Fix、Feature Bundle、Architecture / Refactor、Scientific Validation、Release / Packaging 或 Documentation 模式；
4. 阅读目标文件、调用方、schema、持久状态和现有测试；
5. 明确目标、非目标、文件范围、风险、验收条件和验证命令；
6. 对方案驱动任务持续逐项对照方案，不得到任务末尾才检查遗漏。

架构和安全入口：

- `docs/架构与决策/系统架构.md`
- `docs/安全与审批/安全边界.md`
- `docs/项目概览/能力矩阵.md`
- `docs/文档索引.md`

## 2. 实施顺序

```text
检查范围和现有行为
-> 补复现或 characterization test
-> 实现最小完整调用链
-> 对照方案和不变量自审
-> 运行最小验证矩阵
-> 检查文档影响并同步
-> 检查 diff、Git 状态和生成物
-> Completion Report
```

- Focused Fix 只检查目标调用链，不借机广泛重构。
- Feature Bundle 必须贯通前端、API、服务、运行时/存储和失败状态中适用的层。
- Scientific Validation 必须验证真实数值产物、重载、注册、溯源和参考结果，不能只测路由。
- Release / Packaging 必须分别报告构建、sidecar 启动、packaged smoke、人工 GUI 和真实科学流程证据。
- 不得通过吞异常、降低断言、放宽科学容差或删除测试获得通过。

## 3. 后端验证

使用当前激活环境的 `python`：

```powershell
# 收集
python -m pytest --collect-only -q --basetemp=.pytest_tmp

# 聚焦回归
python -m pytest <focused-test-paths> --tb=short --basetemp=.pytest_tmp

# 全量
python -m pytest --tb=short --basetemp=.pytest_tmp
```

API 测试使用测试应用和 dependency override，不要求预先启动持久后端。测试不得写用户桌面数据库或研究数据。

每次 pytest 结束后，按 `AGENTS.md` 的路径校验要求，只清理仓库根目录直接子项 `.pytest_cache/` 和 `.pytest_tmp*`，随后执行：

```powershell
git status --short
```

必须保留并报告 pytest 原始退出状态；清理不能掩盖失败。

记忆系统变更至少覆盖独立 SQLite schema/迁移、desktop outbox 原子性、
consent epoch 与水位、重复消费、候选过滤、并发 lease/fencing、检索隔离与
预算、科学参数二次确认、Reviewed Plan/Approval Summary hash、忘记/恢复、
启动恢复、API contract 以及中英文前端状态。可使用：

```powershell
python -m pytest tests/unit/test_memory_*.py tests/unit/test_agent_task_commands.py tests/unit/test_approval_summary.py --tb=short --basetemp=.pytest_tmp
```

## 4. 前端和桌面验证

前端源码或配置变化：

```powershell
npm --prefix src/frontend run format:check
npm --prefix src/frontend run typecheck
npm --prefix src/frontend run test
npm --prefix src/frontend run build
```

Agent 自动续跑与全局确认交互变更还应至少覆盖：

```powershell
npm --prefix src/frontend run test -- --run src/features/agent/__tests__/AgentAttentionDialog.test.tsx src/features/agent/__tests__/AgentWorkspace.test.tsx src/features/workspaces/__tests__/PreprocessingWorkspace.test.tsx src/features/workspaces/__tests__/QCReportsWorkspace.test.tsx
```

该组测试验证 action key、关闭/重开、项目切换、已有结构化命令、卡片非 mutation
摘要，以及普通预处理/QC 页面不再暴露旧单节点执行面。

共享 project-runs 行为变化时增加：

```powershell
npm --prefix src/frontend run test:project-runs
```

Lint 相关变化运行：

```powershell
npm --prefix src/frontend run lint
```

Electron 主进程、preload 或 packaging contract 变化：

```powershell
npm --prefix desktop/electron run check
```

Windows 打包、隔离 packaged smoke 和产物保留规则见 `docs/桌面与前端/桌面应用打包.md`。日常验证默认覆盖 canonical `desktop/electron/dist/win-unpacked/`；不要为每次源码变更生成新的 installer 或 portable EXE。

## 5. 本地对齐 CI

`.github/workflows/ci.yml` 是当前 CI 命令权威来源。当前主要矩阵为：

| Job | 环境 | 关键步骤 |
|---|---|---|
| backend | Python 3.11 | 安装依赖、严格 marker 收集、全量 pytest |
| backend Agent Eval | Python 3.11 | 运行 v2 固定 manifest、rule-based/scripted provider 和精确安全门槛；不访问网络 |
| frontend | Node 22 | `npm ci`、typecheck、lint（当前 `continue-on-error`，非阻塞）、format、test、project-runs test、build |
| desktop | Node 22 | `npm ci`、`npm run check` |
| windows-sandbox | Windows + Python 3.11 | 只运行 Windows 沙箱边界、真实受限进程和完整进程树测试；日常 CI 不打包 |

CI 不等价于本地 Windows packaged launch、MATLAB/SPM/DPABI、GPU 或真实研究数据验证。最终报告必须写明没有执行的环境专属检查。

确定性 Agent Eval 可在仓库根目录复现：

```powershell
python scripts/run_agent_evaluation.py --manifest tests/fixtures/agent_eval/v2/manifest.json --provider rule_based --output artifacts/agent-eval/report.json
```

不传 `--allow-network` 时，即使环境中存在密钥也禁止网络 provider。

## 6. 文档同步

每个任务结束前必须执行文档影响检查：

- 新功能：检查新模块、命令、配置、环境变量、依赖、接口、状态、测试和用户流程；
- 修改/重构：搜索旧路径、旧字段、旧接口和旧命令，更新仍然失真的描述；
- Bug/测试失败：判断是否可复发；可复发时补回归测试并把根因转成 `AGENTS.md` 或适当子目录规则；
- 安全/审批/科学能力变化：同步安全文档和能力矩阵；
- 打包/版本变化：同步打包文档、README、`PROJECT_STATE.md` 和当前发布记录中适用的部分。

不得只修改代码。若无需更新 `AGENTS.md` 或某专项文档，Completion Report 必须说明原因。

## 7. 交付自检

交付前必须确认：

- `git diff` 只包含当前任务和原有用户修改；
- rawdata、Approval Gate、路径、审计和科学真实性未被削弱；
- API/schema/前端类型/调用方/持久状态已同步；
- 测试、类型检查、构建和 smoke 结果按层级如实报告；
- pytest 临时目录和本任务生成物已安全处理；
- 文档影响检查完成，旧命令和旧路径没有残留；
- 未提交日志、数据库、用户数据、缓存、frontend dist、PyInstaller 临时目录或未请求的 installer/portable 产物；
- 未经明确要求没有 commit、push、tag、release 或上传。

Completion Report 的字段和 Definition of Done 见根目录 `AGENTS.md`。
