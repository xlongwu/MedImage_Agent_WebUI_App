# Tool Catalog 与 Node Contract

## 权威关系

`NodeContract` 是 pipeline node 的唯一机器可验证合同。Tool Catalog 是由合同派生的
只读展示投影，供 Planner、Plan Review 和 API 使用；它不能覆盖或推断安全字段。

| 表面 | 权威内容 | 用途 |
|---|---|---|
| Plugin Node Registry | `node_id -> runner` | 唯一 runner 注册与执行查找 |
| Node Contract Registry | backend、输入/输出 artifact、参数、审批、风险、write roots、能力与执行性 | 规划、校验、审批和执行前一致性权威 |
| Tool Catalog | 名称、说明、tags，加上从 Node Contract 派生的安全投影 | 模型提示、用户查看、前端展示 |

应用启动和 CI 都运行 consistency check。每个已注册 runner 必须恰有一个完整
Node Contract 和一个 Catalog item；backend、输入/输出、审批、人工确认、风险或
write roots 缺失/不一致时 fail closed。计划专用但不可执行的 node group 必须显式
声明，不得通过 ID 前缀猜测。

## NodeContract v1

核心字段包括：

- `node_id`、`contract_version`、`backend`、`parallel_level`；
- `input_schema`、`parameter_schema`、`output_schema`；
- `requires_approval`、`manual_required`、`risk_level`、`write_roots`；
- pre/postconditions、side effects、resource requirements；
- retry、idempotency、validation policy；
- `capability_level` 和 `executable`。

参数合同明确类型、必填/nullable/default、enum、数值/数组边界和路径读写属性。
未知参数默认拒绝；只有合同显式允许时才能接受 additional parameters。

## ToolCatalogItem

| 字段 | 来源 |
|---|---|
| `id` | Node Contract `node_id` |
| `backend`、`parallel_level` | Node Contract |
| `requires_approval`、`manual_required`、`risk_level` | Node Contract |
| `inputs`、`outputs` | Node Contract artifact schema |
| `name`、`description`、`tags` | presentation-only metadata；缺失时使用明确的中性展示值 |

不存在 ID 前缀 fallback，也不存在安全 metadata fallback。手写 presentation metadata
即使与合同冲突，也不能改变安全投影；consistency check 会报告差异并阻止启动。

## Planner 与 Validator

Planner 只看到 Catalog 中与 executable Node Contract 对应的 node。生成的
`PlannerPlan` 随后按 Node Contract 重新校验 node ID、backend、参数、依赖和路径。
Tool Catalog 本身不授予执行权限；真实执行仍需 Reviewed Plan、Approval Summary、
Execution Ticket、唯一 Gateway 和 runner 侧重验。

## API

| Endpoint | Method | 说明 |
|---|:---:|---|
| `/api/tools/catalog` | GET | 返回完整只读目录 |
| `/api/tools/catalog/{node_id}` | GET | 返回单项；不存在则 404 |
