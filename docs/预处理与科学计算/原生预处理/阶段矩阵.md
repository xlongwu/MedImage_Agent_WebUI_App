# Native Preprocessing Stage Matrix

Status: Phase 01 contract baseline with current implementation note.

This matrix defines the intended native preprocessing stage vocabulary. It is
not, by itself, a runtime claim that every stage is SPM/DPABI equivalent.

## Current Implementation Note

As of 2026-06-28, the native full runner implements the listed native stage
vocabulary and is reachable through the native full API, registered pipeline
nodes, reviewed preprocessing delegation, and frontend native workflow. The
`Initial capability` column below is retained as the original contract
baseline. Current executable capability and validation posture are recorded in
`docs/项目概览/能力矩阵.md` and `docs/预处理与科学计算/原生预处理/验证报告.md`.

The current spatial chain remains native-first but not SPM-equivalent:
realignment is simplified, coregistration is affine/simple, segmentation is
intensity based rather than SPM unified segmentation, and normalization is
affine-only rather than nonlinear deformation based. These stages must stay
labeled simplified or affine-only until approved reference validation changes
their status.

## Notes

- `scaffolded` on stages with existing Python tools means a candidate
  implementation exists elsewhere in the repository, but this phase has not
  selected or migrated a canonical native implementation.
- `simplified` segmentation must not be described as equivalent to SPM unified
  segmentation.
- `affine_only` normalization must not be described as nonlinear SPM
  normalization.
- Metadata and report stages (`input_validation`, `bids_sidecar_validation`,
  `subject_qc`, `group_summary`, `validation_report`, `final_report`) are not
  expected to emit NIfTI/NumPy numerical artifacts. They may emit manifests, QC
  JSON/Markdown, validation JSON, or final reports. These outputs are not
  substitutes for missing numerical artifacts from computational stages.
- Stage IDs in this document are mirrored by
  `src/backend/app/schemas/native_preproc.py`.
