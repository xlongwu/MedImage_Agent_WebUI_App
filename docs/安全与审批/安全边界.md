# 安全边界 (SAFETY_BOUNDARIES)

本文档定义 MedImage Agent 的所有安全边界。所有开发者、Code Agent、以及 LLM 生成的代码都必须遵守这些边界。违反任何一条边界都视为阻塞性 bug。

---

## 1. rawdata 只读

**规则**：用户 `rawdata/`、已登记源数据和任何原始 BIDS/NIfTI 数据**永远只读**。项目内受管的 `data/` 可以保存索引或转换目标，但不得与源数据路径重叠。

- 禁止任何代码（Python、MATLAB、Shell）修改用户 rawdata 或已登记源数据
- 禁止任何 pipeline node 将 rawdata 路径作为 output 目标
- 禁止任何工具删除 rawdata 文件

**实现**：
- 策略层面：`AGENTS.md`、`CLAUDE.md`、本文档明确声明
- 代码层面：`runtime/path_safety.py`、Plan Validator、Tool Catalog、Approval Summary 和执行服务共同检查输入/输出路径与批准范围

**违反后果**：阻塞性 bug，必须立即修复。

---

## 2. Approval Gate

**规则**：所有会写文件、运行 MATLAB/SPM/DPABI、或修改 derivatives 的操作**必须经过 approval gate**。

### 2.1 Agent Task / Reviewed Plan 级审批

- 执行请求必须先持久化 Reviewed Plan 和稳定 Approval Summary，然后停止等待用户确认
- 审批时必须校验 Approval Summary、plan hash、actor 和 scope 未变化
- Agent Task 的 `approve` 与 `approve-recovery` API 不接受调用方在请求体中指定的
  actor；它们要求与服务端启动配置匹配的审批能力令牌，并从该受信任配置派生审计
  actor。令牌或 actor 未配置时必须拒绝审批。
- 审批绑定完成后才能运行执行 dry-run；dry-run 通过后才能创建 Execution Ticket 并经唯一 Execution Gateway dispatch
- 规划阶段不得运行执行 dry-run、runner、外部工具或 dispatch
- plan-only 目标只保存 Reviewed Plan，不创建执行审批、dry-run、ticket、run 或数值产物

### 2.2 Node 合同限制

- 节点的 backend、输入输出、风险和 write roots 必须来自权威 Node Contract
- Tool Catalog 只是 Node Contract 的只读展示，不是执行权限
- 未经当前 Approval Summary、Execution Ticket 和唯一 Gateway 绑定的操作一律安全失败

### 2.3 默认安全

- 计划、Catalog、历史任务或模型输出都不构成当前执行权限
- 未明确审批的操作**安全失败**（fail closed），不会静默执行

**实现位置**：
- `src/backend/app/services/approval_summary_service.py` — 稳定审批摘要和 scope
- `src/backend/app/services/agent_task_command_service.py` — 生命周期命令和审批顺序
- `src/backend/app/services/reviewed_execution_service.py` — 审批绑定的执行前检查
- `src/backend/app/services/execution_ticket_service.py` — Execution Ticket
- `src/backend/app/runtime/execution_gateway.py` — 唯一执行入口
- `src/backend/app/api/agent_task_routes.py` — Agent Task API

## 3. 允许写入目录（白名单）

**规则**：所有文件写入操作限制在以下白名单目录：

| 目录 | 用途 | 示例内容 |
|------|------|---------|
| 项目 `work` root | 运行时状态、中间结果 | `states/<run_id>/`、受控 runtime 状态 |
| 项目 `logs` root | 执行日志 | `pipeline_*.log`、`matlab_*.log` |
| 项目 `derivatives` root | 衍生数据（处理结果） | `alff/`、`reho/` 等 |
| 项目 `reports` root | 报告和 QC 输出 | dataset/QC 报告 |
| 项目 `exports` root（如配置） | 导出包 | 审计或报告包 |

**禁止写入的目录**：
- 用户 `rawdata/` 和已登记源数据（只读）
- `src/` — 源代码
- `examples/` — 示例配置
- `tests/` — 测试文件
- `docs/` — 文档
- 任何系统目录（`/etc/`、`/usr/`、`C:\Windows\` 等）

**实现**：
- `src/backend/app/runtime/path_safety.py` — 路径解析和目录遍历防护
- `src/backend/app/runtime/node_contract_registry.py` — 节点输入输出、风险和 write roots 合同

## 4. LLM advice-only / planning-only

**规则**：应用运行时内接入的 LLM（包括 Claude、GPT 等）只能做**规划、建议、解释**，不能：

- 绕过 Pipeline Executor 直接调用工具
- 直接修改文件系统
- 直接控制 MATLAB/SPM/DPABI 的执行
- 在运行时做出未经人工审批的决策

**允许的 LLM 操作**：
- 生成 pipeline plan（结构化 YAML）
- 提供参数建议
- 解释 QC 报告
- 诊断错误并提供修复建议
- 回答文档问题

可选受控单 Agent Harness 进一步将模型输出限制为两种经 schema 和 capability
catalog 校验的 `ActionEnvelope` 建议：请求用户决定或请求确定性规划器起草计划。
它默认关闭；其 context 和 trace 仅保存脱敏摘要与
hash，不保存原始影像、完整日志、secret、API key 或未过滤聊天记录。Harness
没有 `execute`、`approve`、`write_file`、shell、Ticket 或 Gateway 动作，非法
动作、超预算、stale lease 和模型 JSON 错误均安全停止。Harness 的停止不改变
现有 Approval Gate、Execution Ticket 或唯一 Execution Gateway 的权限边界。
Harness wake 只能由 command 或 post-run monitor owner 登记；读取接口绝不唤醒或
claim。provider 不可用时可在已停止的 model attempt 之外明确切换到确定性规划路径，
并记录来源、目标和原因；该路径必须生成新的 plan/context hash，不能复用已有审批。

Harness Context v2 只接收当前 Action 所需的固定 typed sections。每个分区都带来源
hash 并受大小上限约束；绝对路径转换为 project/artifact ref，provider credential、PHI、
原始影像、完整模型响应、traceback、stdout 和 stderr 一律排除。超限时只整项删除
非必要分区；必需安全上下文仍超限则在模型调用前以
`AGENT_CONTEXT_LIMIT_EXCEEDED` 停止。

Harness Product Skill 只允许一个随应用打包的静态资源：规划证据复核。它位于
`src/backend/app/agent_skills/`，通过代码内 fixed allowlist、严格
manifest、capability catalog、Context section allowlist 与内容 hash 校验；不得扫描目录、
远程下载、动态安装或接受用户上传。Skill 只能读取 manifest 声明的脱敏 Context 分区，
且位于 Action schema 之前的固定 prompt 位置，不能增加 Action、数据读取、文件、网络、
审批或执行权限。Context/step/model-call audit 只保存 ID、版本、hash、分区和结构化
`AGENT_SKILL_UNAVAILABLE` 错误码，不保存正文。资源缺失或损坏时仅回退基础安全 prompt，
确定性规划路径保持可用。仓库 `.agents/skills/` 是开发 Agent 指令，不属于产品运行时
能力或后端打包资源。

### 4.1 Agent 自动化等级与当前审批

Harness 的 capability catalog 是唯一的模型 Action allowlist。每个 Action 都必须声明
automation level、允许 lifecycle state、Context 分区、输出类型、是否需要当前审批和
副作用类别；未声明或不完整的能力一律拒绝。模型只能调用 A0/A1，A2 不是模型 Action。

| 等级 | 允许范围 | 当前确认 |
| --- | --- | --- |
| A0 | 读取 allowlisted 的 project/config/catalog/plan/run/artifact/Observation 摘要 | 不需要 |
| A1 | 写受管的 Harness attempt/context/step/action/trace，并生成决定或请求确定性规划 | 不需要 |
| A2 | 按已批准 Execution Ticket 的精确 scope 运行、monitor、observe、evaluate | 一次 Reviewed Plan 审批后自动推进 |
| A3 | 修改科学答案、goal、Memory/Skill 影响的计划输入、node/backend/params/dependency、输入/输出 root 或 overwrite | 生成新 Reviewed Plan 和新 Approval Summary |
| A4 | rawdata 写入、任意 shell/Python、Gateway bypass、临床结论 | 永久禁止 |

模型置信度、Memory、Skill 或模型声称“用户已批准”都不能改变自动化等级。
动作是封闭的 typed structure，不能携带通用 payload、shell、执行、路径、URL、Ticket、审批
或 credential 字段。Context、Evidence 和 Trace 仅可
返回 `project://`、artifact ID 或受控相对引用，跨项目 ID 必须由后端 scope 检查拒绝。

Approval Summary 必须绑定 project、Reviewed Plan、plan/normalized-plan/planning-input hash、
EvidenceSnapshot、science answers hash、MemoryContext、provider/prompt、实际 Skill hash（如有）、
node/backend、实际 plan payload（包括 input/output root 与 overwrite）、write roots、expiry。审批时重建摘要并验证 trusted principal；
任何 binding 漂移都在 dry-run 前以 stale 错误拒绝。批准后的顺序固定为：验证摘要和 actor
→ 绑定审批的 dry-run → 一次性 Execution Ticket → 唯一 Gateway dispatch → monitor/
Observation/Goal Evaluation。Harness 不接触 approval token、ticket secret 或 Gateway callable；
retry/recovery 保持其独立当前审批，改变 contract 时回到 A3。

**实现**：
- 架构层面：Agent Runtime 的 Plan-then-Execute 模式
- 代码层面：所有 LLM 输出经过 Plan Validator 和 Approval Gate
- `src/backend/app/advisor/advisor_safety.py` — Advisor 安全边界控制

### 4.2 记忆系统安全边界

- 安装级 `enabled/generation/use` 与项目级 `generate/use` 双层门控默认关闭；
  读侧预览无副作用。门控关闭时返回带 `disabled` 状态的 typed 空上下文且不探测
  memory store；门控已启用但 memory DB health 或 outbox preflight 失败时必须以
  `MEMORY_STORE_UNHEALTHY` / `MEMORY_OUTBOX_PREFLIGHT_FAILED` 等结构化错误阻断规划，
  不得静默使用空上下文继续。可恢复的积压、重试、dead-letter、过期 lease 或待处理
  forget 投影为 `partial` 和 warning codes，不得伪装为 healthy。
- 记忆只允许项目作用域，不建立跨项目 profile；原始影像、受试者标识、
  secret/token、完整日志、任意工具输出、绝对 rawdata 路径和 prompt injection
  内容在候选生成前拒绝或清洗。
- 记忆不是执行权限、审批、能力等级、科学有效性、临床结论或当前环境事实。
  科学参数只能作为建议；当前任务未再次确认时必须停在科学决策状态。
- 规划实际使用的记忆版本和 `MemoryContext` hash 必须进入 Reviewed Plan 与
  Approval Summary；记忆更新不得追改已持久化或已审批计划。
- 忘记操作先写 desktop forget ledger，再清除 memory SQLite 明文并保留最小
  tombstone；在向调用方报告成功前，必须验证 SQLite WAL 已完成 `TRUNCATE`。
  WAL 被活动读者占用时忘记操作必须失败关闭，并允许同一命令在占用解除后重试。
  旧 outbox 事件不得自动恢复已忘记 generation。恢复必须由用户重新提供内容并
  产生新 generation。
- 可读文件投影默认关闭，只能原子写入项目批准的 `work/memory/`，不能作为
  权威源、不能写 rawdata，也不能被 planner 直接读取。

## 5. MATLAB / SPM / DPABI 执行限制

**规则**：MATLAB/SPM/DPABI 的执行受严格控制。

### 5.1 环境变量门控

- `MEDIMAGE_MATLAB_ENABLED` 环境变量控制 MATLAB 是否可用
- 默认 `false`，MATLAB 调用被阻止
- 即使 `true`，仍需 `approved=true`

### 5.2 MATLAB 执行约束

- MATLAB 脚本只从 `matlab/` 目录加载
- MATLAB 工作目录限制在 `outputs/work/` 和 `outputs/logs/`
- MATLAB 不能访问 `data/` 以写入模式
- MATLAB 输入文件只能是 rawdata 或上游节点的 derivatives 输出

### 5.3 DPABI 执行约束

- DPABI 函数禁止运行 `DPARSF_run`、`DPARSFA_run`、DPABI GUI
- 只允许单函数 wrapper 模式
- DPABI backend 是 contract-only：生成 spec 文件但不执行（除非明确审批）

**实现位置**：
- `src/backend/app/tools/matlab_runner.py`
- `src/backend/app/tools/dpabi_runner.py`
- `src/backend/app/tools/dpabi_safety.py`（如有）

## 7. API Key / Secret 管理

**规则**：不允许把 API key、绝对私有路径、实验数据路径写死进代码或文档。

**要求**：
- API key 通过环境变量注入（如 `OPENAI_API_KEY`、`ANTHROPIC_API_KEY`）
- 私有路径通过项目配置文件（YAML）或环境变量指定（如 `MEDIMAGE_DATA_ROOT`）
- 不允许在代码中使用绝对路径引用外部数据
- `.env` 文件在 `.gitignore` 中

**检查**：任何 PR 包含 API key 或绝对路径的硬编码，直接拒绝。

## 9. Path Safety 机制

**规则**：所有通过 API 的文件访问必须经过与接口作用域匹配的路径安全
策略，不能接受任意路径。

**实现**：`src/backend/app/runtime/path_safety.py`

- 所有路径强制归一化（resolve）
- 禁止目录遍历攻击（`../` 逃逸）
- 只允许访问白名单目录：`examples/`、`work/`、`logs/`、`reports/`、`memory/`、`specs/`
- 只允许读取白名单后缀：`.json`、`.yaml`、`.yml`、`.md`、`.txt`、`.csv`、`.html`、`.log`

上述仓库根白名单适用于通用 `/api/files/read` 和 `/api/logs/read` 代理。
项目 run/artifact 接口使用更窄的 project/run 输出根与 artifact ID 重新发现，
不能用该通用白名单扩大项目产物访问范围。
- 系统敏感路径（`/etc/`、`/proc/`、`C:\Windows\` 等）不可访问

## 10. Node Contract Permission Boundaries

**规则**：`runtime/node_contract_registry.py` 的 `NodeContract` 是节点 backend、
输入输出、参数、风险、确认和 write roots 的唯一权威。Tool Catalog 只展示合同字段，
不允许 ID 前缀或安全 metadata fallback。启动一致性检查发现缺失或冲突即 fail closed。
执行仍须经过 Agent Task 的 Approval Summary、Execution Ticket、安全路径、allowlist
与唯一 Gateway；不能把 Catalog、历史任务或已移除的文件型计划当作权限来源。

---

## 11. 前端隔离

**规则**：前端只能通过后端 HTTP API 与系统交互，不能直接操作本地文件系统。

**约束**：
- 前端所有文件读写通过 `/api/files/read`、`/api/logs/read` 等代理端点
- 前端不能调用 `fs` 模块（Node.js）直接读写文件
- 前端不能直接执行 MATLAB/SPM 命令
- Electron 桌面应用的主进程文件操作受同样限制（通过 `preload.cjs` 桥接）
