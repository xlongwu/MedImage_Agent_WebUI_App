# MedImage Agent User Guide

## Quick Start

```bash
# Start backend
uvicorn src.backend.app.main:app --host 127.0.0.1 --port 8000

# Start frontend
cd src/frontend && npm run dev
```

## Agent-first workflow

After choosing a registered project, the default **Agent** page is the main
research workflow:

1. Describe the desired research output in one goal.
2. If the project evidence leaves a scientific ambiguity, answer the one
   displayed decision batch (at most six items) and submit it once. The Agent
   does not choose an atlas, GSR policy, conflicting TR, template,
   output-conflict policy, or experimental backend for you.
3. Review one approval card. It shows the reviewed stages, write roots,
   external-tool boundary, limitations, and rawdata read-only guarantee.
4. When reviewed execution is enabled, approve once. Progress and the
   evidence-backed result update automatically; no manual dry-run, validation,
   report generation, or refresh step is part of the standard path. Advanced
   task details can show only the redacted Agent activity, never prompts, raw
   responses, credentials, absolute paths, or source images.

Reviewed execution is disabled by default and approval does not override this
environment gate. Set the gate before starting the backend, then restart it:

```powershell
$env:MEDIMAGE_ENABLE_REVIEWED_EXECUTION = "1"
uvicorn src.backend.app.main:app --host 127.0.0.1 --port 8000
```

The packaged desktop application inherits the same environment setting when it
is launched from that PowerShell session:

```powershell
$env:MEDIMAGE_ENABLE_REVIEWED_EXECUTION = "1"
& "C:\path\to\MedImage Agent.exe"
```

The application never enables this gate automatically. If it is disabled, no
computation starts and the Agent page explains how to enable it before the
unchanged reviewed plan is approved again. External MATLAB/SPM/DPABI environment
gates and optional GPU capability/resource checks remain separately controlled
unless explicitly configured.

The **Runs** page provides lineage and evidence. **Advanced mode** in Settings
reveals the established specialist workspaces for inspection and debugging; it
does not bypass backend approvals or tickets.

If one subject fails and the stored evidence supports a bounded recovery, the
Agent shows the affected and untouched scope. One recovery approval executes
only the recommended eligible candidate through a one-use child ticket. Scope
changes require a new plan and approval.

## Running rs-fMRI Pipelines

Technical compatibility CLIs remain available for direct Pipeline Runtime
validation. They are advanced/developer surfaces, not the standard Agent Task
workflow, and they do not replace Reviewed Plan approval, execution tickets, or
the reviewed gateway. For example:

```bash
python -m src.backend.app.tools.run_rsfmri_alff_falff_cli examples/project_config_dataset.yaml examples/pipeline_rsfmri_alff_falff.yaml --approve
```

For compatibility pipelines containing SPM nodes, `--approve` is mandatory.
The flag only marks the generated compatibility pipeline copy as reviewed;
MATLAB/SPM environment and external-execution gates must still pass, otherwise
the SPM steps fail safely.

## API Access

All results are accessible via REST API at `http://127.0.0.1:8000`. Key endpoints:
- Agent tasks: `/api/projects/{project_id}/agent/tasks`
- Preprocessing: `/api/rsfmri/spm-{stage}`
- QC: Motion, Registration, Tissue, Normalization, Smoothing
- Post-processing: Nuisance Regression, Temporal Filtering
- Metrics: ALFF/fALFF, ReHo, Functional Connectivity
- Reports: Group Summary, Report Export, Report Validator
- Release: `/api/release-readiness`

## Safety

This is a non-clinical research tool. Registered project data may include
research imaging data, but source `rawdata` remains read-only. Execution always
uses reviewed plans, the Approval Gate, a server-issued Execution Ticket, and
the registered Pipeline Runtime. External tools remain disabled by default and
require their own reviewed environment gates. The UI never establishes
clinical diagnosis or treatment claims.
